# Pure Run 战斗地图 10×10 改造计划

## Summary

将当前战斗逻辑棋盘从 `18×18` 改为固定 `10×10`，统一采用 `(0…9, 0…9)` 局部格坐标，并同步调整运行时代码、遭遇与测试配置、Unity 场景、Tilemap 构图、固定全图相机和空间相关战斗数值。

本计划先建立一个可独立进入的 `10×10` 探针，自动验证通过后暂停并等待用户进行视觉与操作确认；只有获得明确确认，才替换正式 `Test1` 战场并清理旧 `18×18` 专用内容。

成功标准：

- 正式战斗棋盘严格为 `100` 个逻辑格，所有运行时与测试坐标均落在 `0…9`。
- 保持固定全图相机，在 `16:9`、`16:10`、`21:9` 下不裁格、不被核心 UI 遮挡，且单位和技能表现比当前 `18×18` 构图更清晰。
- 普通遭遇保持 3 名玩家对 3–4 名敌人，首回合通常需要移动后接敌，基准普通战斗中位时长为 4–6 个完整轮次。
- 参考《喵喵的结合》的空间节奏，但不复制其地图资产、场景结构、美术方案或完整伤害体系。

- 当前玩家移动为 5；怪物移动约为 6–12；多数玩家技能射程为 4–6。直接套入 10×10 会导致移动和远程覆盖过强。
- 本地解析的《喵喵的结合》关卡配置共 2361 个 `.lvl`，主次尺寸字段均为 `10×10`；其原始角色移动声明多数集中在 2–4，能力射程多数集中在 1–5。该数据只作为空间比例参考。

## Interface and Data Contract

### 统一棋盘规格

- 增加单一 `BattleBoardSpec`，声明 `Width = 10`、`Height = 10`、最小坐标 `(0,0)`、最大坐标 `(9,9)`，并提供统一的 `Contains` 校验。
- `BattleBoardSpec` 是当前固定棋盘规则，不设计任意地图尺寸、世界坐标偏移兼容层或旧/新双坐标模式。
- Background Tilemap 自身坐标直接使用 `0…9`；运行时不再额外换算旧的 `18…35` 世界格坐标。

### 布局与出生接口

- 为 `BattleLayout` 增加 `PartySpawnCells`；现有 `SpawnCells` 继续表示敌人出生格，`BlockedCells` 继续表示战斗期间写入并在清理时恢复的阻挡格。
- 为运行时 `EncounterConfig` 增加对应的玩家出生格数据；`ResolvedEncounter.ToEncounterConfig()` 必须完整复制玩家出生、敌人出生和阻挡数据。
- 正式 `SpawnPartyUnits` 按当前遭遇布局的 `PartySpawnCells` 和队伍顺序生成。缺失、越界、重复、不可行走或已占用均视为配置错误，不再回退到相机 viewport 选格。
- 测试模式继续以 `BattlePartyTestConfig` 的显式出生格为权威，但其坐标同样迁移为 `0…9`。

## Implementation

### 1. 建立可切换的 10×10 探针

- 新建独立探针场景及配套测试配置，暂不修改正式战斗入口和原 `Test1`。
- Background Tilemap 必须恰好有 100 个连续逻辑地格；装饰性边界不得放入供 `TilemapCellManager` 读取的 Tilemap。
- 保持现有 Grid Cell Size `(1, 0.5, 1)`、64×32 菱形格、角色资源和主要地砖风格。
- 重构边界、中央障碍和分路构图；装饰层只负责表现，Foreground 中影响路径的物体必须与 `BlockedCells` 一致。

探针使用以下首轮布局基线：

| 布局 | 玩家出生格 | 敌人出生格 | 永久阻挡格 |
|---|---|---|---|
| `open` | `(1,4) (1,5) (2,4)` | `(6,4) (7,3) (7,5) (8,4)` | 无 |
| `center_blocker` | 同上 | `(6,3) (6,6) (7,4) (7,5)` | `(4,4) (4,5) (5,4) (5,5)` |
| `split_flank` | 同上 | `(6,2) (6,7) (7,2) (7,7)` | `(4,3) (5,4) (4,6) (5,5)` |
| `Special` | 使用 `open` 玩家位 | 单个精英位于 `(7,4)` | 无 |

验收：全部出生与阻挡格唯一、合法；敌我区域连通；普通开放图存在少量首回合远程目标，近战通常需要先移动；中央和分路布局不得形成唯一死路或永久封锁。

### 2. 固定全图相机与显示构图

- 增加仅在场景初始化或分辨率变化时工作的战斗棋盘相机适配组件，以逻辑 Background Tilemap 的渲染边界、画幅和安全留白计算相机中心与正交尺寸。
- 计算原则为同时容纳垂直和水平方向的 padded bounds；背景继续由现有 `BattleBackdropFitter` 跟随。相机不响应拖动、滚轮、键盘或手柄输入。
- `16:9` 下正交尺寸预计约为 `2.9–3.2`，但最终以边界算法为权威，不将该经验值硬编码成跨画幅常量。
- `16:9`、`16:10`、`21:9` 均必须显示全部 100 格；超宽可增加背景留边，但不得放大到裁格。

视觉检查覆盖：

- 角色像素/线条清晰度和贴图过滤。
- 单位、尸体、落矛、障碍与地面的排序关系。
- 选格、移动范围、技能范围、AOE 地面提示与菱形格对齐。
- 投射物、命中特效、伤害数字和 UI 在更近相机下不失真、不遮挡主要目标。
- 背景渐变、噪点和暗角在放大后不过强。

### 3. 迁移坐标和遭遇数据

- 将 `EncounterCatalog` 的全部布局、N1–N6、E1、E2、Special 转为局部坐标，并写入明确的玩家出生格。
- 迁移 `DefaultTestParty`、默认/尸体测试遭遇、`basic_melee.json` 及所有由地图布局测试覆盖的坐标数据。
- 更新 Editor Scene GUI 中出生点拖拽/显示逻辑，使其显示局部格坐标并拒绝越界位置。
- 移除生产出生流程中基于相机可见范围和 viewport 距离的战术选格；保留与地图无关的资源加载和角色绑定流程。

### 4. 空间数值重标定

移动与先攻解耦：

- 战斗移动点统一改为 `Clamp(CeilToInt(Speed / 2f), 1, 4)`。
- Speed 和 `Speed × 2` 的先攻计算保持不变。
- 结果基线：玩家 Speed 5 → 移动 3；Speed 6 怪物 → 3；Speed 8/12 怪物 → 4；Speed 4 召唤物 → 2。

玩家技能射程：

- 火球等现有射程 4 保持。
- 寒冰箭、闪电、伤害加深、恐惧、骨矛等射程 5 统一降至 4。
- 瞬移 6 → 4。
- 毒矛和召回长矛 6 → 5，保留亚马逊的长射程身份。
- 火魔召唤 3、突刺 2/3、连续刺击 3、分身 2、寒冰反弹半径 3 保持。
- 骷髅召唤的尸体选择 `999` 暂时保留，明确视作全图例外并增加回归测试。

怪物技能与 AI：

- Charge Strike 4 → 3。
- Ranged Attack `2–5` → `2–4`；Heavy Shot 5 → 4；远程 AI 偏好距离 `3–5` → `2–4`。
- Area Blast 中心射程 4 → 3，半径 2 保持；AOE AI 偏好距离收缩为 `2–3`。
- Support 诅咒 5 → 4，偏好距离收缩为 `2–3`。

首轮不调整：

- 职业与怪物基础伤害、HP/MP 派生、回合/战后恢复。
- N1–N6 的 3–4 名敌人组成。
- E1/E2/Special 的既有生命与输出倍率。

数值回归规则：

- 用同一基准三人队测试 N1–N6，目标中位时长为 4–6 个完整轮次。
- 单个配方中位数低于 4 轮时，只将该配方 HP 倍率按 `+0.1` 调整，首轮上限 `1.2`；高于 6 轮时按 `-0.1` 调整，首轮下限 `0.8`。
- 只有轮数已达标但生存压力仍明显异常，才按 `0.05` 步长调整该配方输出倍率。
- 不通过改职业技能伤害来补偿地图压缩，避免空间变化和伤害体系重做互相污染。

### 5. 探针审批与正式推广

- 探针完成自动验证后停止实施，并向用户提供后台可取得的对比截图/数据；若后台无法完成视觉检查，明确标记 `manual_visual_qa_pending`，不得抢占前台焦点。
- 用户未明确批准前，不修改正式战斗入口、不覆盖 `Test1`、不删除旧 `18×18` 内容。
- 用户批准后，将探针内容推广为正式 `Test1`，更新默认场景和配置引用，再删除临时探针与仅服务旧 `18×18` 的配置/断言。
- 删除前核对引用，确保没有其他场景、测试或工具仍依赖旧坐标范围。

## Test Plan

### Editor / 静态校验

- 棋盘边界为 `(0,0)` 到 `(9,9)`，Background Tilemap 恰好 100 格。
- Foreground、装饰和阻挡配置不会产生额外逻辑格。
- 所有敌我出生格和阻挡格均在界内、唯一且符合可行走/阻挡语义。
- 每个布局至少存在一条敌我连通路径；所有 N1–N6、E1、E2、Special 均可解析。
- 普通遭遇保持 3–4 名敌人；Special 保持单精英规则。
- 资产、Prefab 和脚本的 `.meta` 配对与 GUID 引用完整。

### EditMode / PlayMode

- `BattleBoardSpec.Contains` 的边界内外测试。
- 新移动公式覆盖 Speed 1、4、5、6、8、12 和超过上限的情况，并验证先攻未改变。
- 正式队伍按布局出生；非法、重复、阻挡或占用出生格给出明确错误且不会静默改位。
- 遭遇阻挡在单位生成前生效、战斗清理后恢复。
- 骷髅尸体选择、火魔生成、诱饵、落矛/召回在 10×10 边缘和拥堵环境下正确。
- LOS、冲锋、击退、AOE 半径、范围提示和点击命中在棋盘边缘不越界。
- 相机适配在 `16:9`、`16:10`、`21:9` 的几何断言中容纳完整棋盘。

### 玩法回归

- N1–N6 各至少运行 3 次基准战斗，记录轮数、玩家伤亡和首轮可攻击目标数。
- 普通遭遇总体中位时长落在 4–6 轮；开放图首轮有行动价值，但不能普遍出现敌我全员无需移动即可攻击。
- E1、E2、Special 各完成至少一次完整冒烟战斗。
- 运行与战斗生成、地图布局、技能范围、召唤、尸体、投矛、AI 和 UI 相机稳定性相关的现有测试集。

### Unity 与项目验证

- 所有 C# 修改完成后执行 `refresh_unity` 并确认编译无错误。
- 运行目标 Editor/PlayMode 测试，再运行可用的相关完整测试套件；若 Unity 返回 `editor_unfocused`，不得抢焦点，需将完整套件和视觉验证标记为未完成。
- 运行 `python Tools/okf/catalog_impact.py report --worktree`，更新本任务影响的战斗/地图/数值权威文档，再按实际 scope 执行 `sync --worktree --scope <scope> --write`。

## Risks and Assumptions

- 10×10 会放大射程、AOE、控制、召唤和占格价值，因此不能只裁 Tilemap；必须同时完成坐标、出生、移动、技能范围和 AI 偏好迁移。
- `split_flank` 在小地图上最容易形成拥堵或绕路过长，若连通性测试通过但实玩仍拖沓，只允许调整其阻挡格和出生格，不扩大棋盘。
- AOE 半径 2 在 100 格棋盘上影响比例明显上升，但首轮保留以维护技能身份；若造成友军 AI 长期无合法施放中心，应优先调整布局/AI 候选，不先削伤害。
- 本轮固定 3 名玩家和 3–4 名敌人；召唤物、尸体、诱饵和落矛形成的动态密度纳入测试，不据此预先增加敌人数量。
- 旧讨论中“不照搬 Mew 固定地图设计”的美术与架构约束继续有效；当前用户明确指定的 `10×10` 尺寸和数值节奏参考覆盖了旧的尺寸犹豫，但不授权复制外部游戏资产。
