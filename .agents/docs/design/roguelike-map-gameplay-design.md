# Roguelike地图玩法设计文档 — 方案C: 混合式区域探索

> **版本**: v1.0  
> **日期**: 2026-05-12  
> **状态**: 设计完成，待实现规划  
> **关联计划**: [.agents/docs/plans/战斗系统演进计划.md](.agents/docs/plans/战斗系统演进计划.md)

---

## TL;DR

**核心玩法**: FTL式逐步探索 + 杀戮尖塔式分支路径规划，融合为"区域主题化"的地图探索体验。

**一句话描述**: 玩家在3个主题区域中逐步探索分支路径，通过事件选择、商店购买、战斗奖励来构筑队伍，最终击败Boss。

**关键创新点**:
- 区域主题影响战斗（森林=树木掩护，城堡=更多精英）
- 区域过渡事件（选择进入下一区域的方式，影响初始状态）
- 复杂事件系统（FTL式多选项事件，基于职业/装备/属性）

---

## 设计决策汇总

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 地图可见性 | FTL式逐步探索 | 核心玩法是探索冒险 |
| 外部压力 | 无 | 让玩家自由探索，不焦虑 |
| 单局时长 | 30-45分钟 | 中等深度，适合重复游玩 |
| Mystery节点 | 复杂事件分支 | FTL式事件系统，多选项+条件判断 |
| 资源系统 | 仅金币 | 简单直接，降低认知负担 |
| 失败惩罚 | 完全重来 | 经典Roguelike体验 |
| 地图规模 | 3个区域，共8层 | 匹配30-45分钟时长 |

### 区域内结构（尖塔式分支）

```
Layer 0 (起点):        ●

                  │    │    │
```

**每层特征**:
- 宽度: 3-5个节点
- 连接: 每个节点连接到下一层的1-3个节点
- 可见性: 只能看到当前层和下一层（逐步揭示）

### 区域定义

#### 区域1: 森林外围 (Forest Outskirts)

**主题**: 自然、野兽、神秘

**节点分布**:
| 节点类型 | 概率 | 说明 |
|----------|------|------|
| MinorEnemy | 35% | 野兽类敌人 |
| EliteEnemy | 10% | 稀有野兽/德鲁伊 |
| Mystery | 25% | 自然主题事件 |
| Store | 10% | 游商/德鲁伊商店 |
| Treasure | 10% | 隐藏宝箱 |
| RestSite | 10% | 安全营地 |

**战斗影响**:
- 树木地形: 提供掩护，远程攻击命中率-15%
- 草地地形: 移动力+1
- 河流地形: 移动力-1，但火焰伤害+20%

**事件主题**: 古老祭坛、迷路的旅人、野兽巢穴、神秘泉水

#### 区域2: 城堡外围 (Castle Outskirts)

**主题**: 战争、政治、阴谋

**节点分布**:
| 节点类型 | 概率 | 说明 |
|----------|------|------|
| MinorEnemy | 30% | 士兵/佣兵 |
| EliteEnemy | 20% | 骑士/法师 |
| Mystery | 20% | 政治事件 |
| Store | 15% | 军需官/黑市 |
| Treasure | 5% | 贵族藏宝 |
| RestSite | 10% | 旅店/军营 |

**战斗影响**:
- 城墙地形: 防御+20%，但移动力-1
- 街道地形: 移动力+1，但无掩护
- 广场地形: 无特殊效果

**事件主题**: 政治阴谋、间谍活动、战俘交换、贵族委托

#### 区域3: Boss领地 (Boss Domain)

**主题**: 黑暗、危险、决战

**节点分布**:
| 节点类型 | 概率 | 说明 |
|----------|------|------|
| MinorEnemy | 25% | 强化敌人 |
| EliteEnemy | 25% | 精英守卫 |
| Mystery | 15% | 危险事件 |
| Store | 5% | 最后的补给 |
| Treasure | 10% | 稀有奖励 |
| RestSite | 10% | 最后的休整 |
| Boss | 10% | 区域Boss |

**战斗影响**:
- 黑暗地形: 命中率-10%
- 陷阱地形: 随机触发伤害
- Boss房间: 无特殊地形，但Boss有独特机制

**事件主题**: 黑暗仪式、古代封印、背叛、最终抉择

## 节点类型详细设计

### 1. MinorEnemy (普通战斗)

**触发**: 点击节点 → 进入战斗场景

**战斗配置**:
- 敌人数量: 2-4个普通敌人
- 敌人等级: 基于当前区域和层数
- 地形: 基于区域主题

**胜利奖励**:
- 金币: 10-30 (基于敌人强度)
- 经验值: 队伍获得经验
- 掉落: 小概率装备/消耗品

### 2. EliteEnemy (精英战斗)

**触发**: 点击节点 → 进入战斗场景

**战斗配置**:
- 敌人数量: 1-2个精英敌人 + 1-2个普通敌人
- 敌人等级: 高于当前层数2-3级
- 地形: 基于区域主题，但更有利敌人

**胜利奖励**:
- 金币: 40-80
- 经验值: 大量
- 掉落: 高概率稀有装备 + 必定获得1个消耗品

**视觉标识**: 节点图标有红色边框，提示难度

### 3. Mystery (事件节点) ⭐核心玩法

**触发**: 点击节点 → 弹出事件UI

**事件结构**:
```
[事件标题]
[事件描述文本]

选项A: [选项文本]
  → 结果: [奖励/惩罚/战斗/无]
  → 条件: [需要职业/装备/属性]

选项B: [选项文本]
  → 结果: ...

选项C: [选项文本] (可选)
  → 结果: ...
```

**事件类型**:

#### 类型A: 纯奖励事件
**示例**: "你发现了一个古老的宝箱"
- 选项A: 打开它 → 获得金币/装备 (80%成功，20%陷阱)
- 选项B: 离开 → 无奖励

#### 类型B: 风险-回报事件
**示例**: "一个受伤的商人请求帮助"
- 选项A: 帮助它 → 消耗20HP → 获得稀有装备
- 选项B: 抢劫它 → 获得金币 → 可能触发战斗
- 选项C: 离开 → 无

#### 类型C: 条件判定事件
**示例**: "一道魔法封印挡住了去路"
- 选项A: 用力量破坏 (需Barbarian或力量>15) → 成功:通过，失败:战斗
- 选项B: 用智慧解开 (需Mage或智力>15) → 成功:获得Buff，失败:陷阱
- 选项C: 绕路 → 无奖励，但安全

#### 类型D: 连锁事件
**示例**: "你发现了一个神秘祭坛"
- 选项A: 祈祷 → 获得随机Buff
- 选项B: 破坏 → 触发战斗，但胜利后获得更好奖励
- 选项C: 标记位置 → 无即时奖励，但后续某节点变为Treasure

**事件数据表结构**:
```json
{
  "eventId": "forest_altar_001",
  "title": "古老的祭坛",
  "description": "森林深处有一座被藤蔓覆盖的祭坛...",
  "region": "Forest",
  "options": [
    {
      "text": "祈祷",
      "conditions": [{"type": "class", "value": "Mage"}],
      "success": {"type": "buff", "buffId": "nature_blessing"},
      "failure": {"type": "nothing"}
    },
    {
      "text": "破坏",
      "success": {"type": "battle", "enemyGroup": "forest_guardians"},
      "failure": null
    },
    {
      "text": "离开",
      "success": {"type": "nothing"},
      "failure": null
    }
  ]
}
```

### 4. Store (商店)

**触发**: 点击节点 → 弹出商店UI

**商店机制**:
- 商品数量: 4-6个物品
- 商品类型: 装备(50%) / 消耗品(30%) / 技能书(20%)
- 价格: 基于物品稀有度和当前区域
- 刷新: 商店节点不可重复访问

**商品示例**:
- 普通装备: 50-100金币
- 稀有装备: 150-300金币
- 消耗品(药水): 20-50金币
- 技能书: 100-200金币

**UI设计**:
- 左侧: 商品列表（图标+名称+价格）
- 右侧: 选中商品详情 + 购买按钮
- 顶部: 玩家当前金币

### 5. Treasure (宝藏)

**触发**: 点击节点 → 直接获得奖励

**奖励池**:
- 金币: 30-60
- 装备: 中概率获得当前区域主题装备
- 消耗品: 必定获得1-2个
- 特殊: 小概率获得"区域钥匙"（解锁隐藏路径）

**视觉表现**: 节点图标为宝箱，点击后播放开箱动画

### 6. RestSite (休息站)

**触发**: 点击节点 → 弹出选择UI

**选项**:
- **休息**: 恢复队伍50%最大HP
- **训练**: 选择一个角色，提升1点随机属性
- **冥想**: 选择一个角色，恢复全部MP
- **修理**: 修复装备耐久（如有耐久系统）

**限制**: 每个RestSite只能选择一次

### 7. Boss (Boss战)

**触发**: 点击节点 → 进入Boss战斗场景

**特征**:
- 唯一节点，每个区域最后层
- Boss有独特机制和多阶段
- 胜利后进入区域过渡事件

**胜利奖励**:
- 大量金币: 100-200
- 稀有装备: 必定获得1件
- 区域通关奖励: 全队属性+1 或 特殊Buff

## 区域过渡系统

### 触发条件
到达区域最后一层的Boss节点并胜利后，触发区域过渡事件。

### 过渡事件结构
```
[区域完成提示]
"你击败了森林守护者，前方出现了三条路..."

选项A: [选择描述]
  → 影响: [下一区域初始状态]
  
选项B: [选择描述]
  → 影响: ...
  
选项C: [选择描述] (可选)
  → 影响: ...
```

### 过渡事件示例

**从区域1到区域2**:

"你穿过了森林边缘，城堡的轮廓出现在远方..."

- **选项A: 走主路** → 安全，但无额外奖励，下一区域正常生成
- **选项B: 探索侧道** → 50%概率发现宝藏，50%概率遭遇伏击（进入战斗），下一区域第一个节点变为Mystery
- **选项C: 跟随商队** (需支付50金币) → 下一区域初始获得1个消耗品，商店价格-10%

**从区域2到区域3**:

"城堡的大门敞开着，黑暗从中涌出..."

- **选项A: 正面突破** → 下一区域前两层敌人+1
- **选项B: 寻找密道** (需盗贼或敏捷>15) → 跳过下一区域第一层，直接进入第二层
- **选项C: 休整准备** → 全队恢复30%HP，但下一区域精英敌人+10%

## 资源系统

### 金币

**获取途径**:
- 战斗胜利: 10-80金币
- 事件奖励: 0-100金币
- 宝藏节点: 30-60金币
- 出售装备: 装备价值的30%

**消耗途径**:
- 商店购买: 20-300金币
- 过渡事件: 0-50金币
- 事件选项: 某些选项需要支付金币

**设计原则**:
- 单局总金币收入: 约500-800金币
- 玩家需要做出选择: 买装备 vs 存金币 vs 投资过渡事件

### 经验值

**获取途径**:
- 战斗胜利: 基于敌人强度
- 事件奖励: 某些事件给经验

**作用**:
- 角色升级: 提升基础属性
- 技能解锁: 某些技能需要等级

## 可见性系统

### 逐步揭示规则

```
当前层 (Layer N):     完全可见 ✅
下一层 (Layer N+1):   可见节点类型和连接 ✅
下下层 (Layer N+2):   完全隐藏 ❌
```

**揭示时机**:
- 到达新层时，揭示下一层
- 某些事件/装备可以"侦察"更远的层
- Boss节点在到达区域最后层前始终隐藏类型（显示为Mystery）

### 节点状态

```
未揭示:    灰色问号图标
已揭示:    显示真实节点类型图标
可到达:    高亮边框，可点击
已访问:    半透明，不可再次点击
当前位置:  玩家头像/标记
```

## 与战斗系统的衔接

### 战斗前传递数据

```csharp
// 从地图传递到战斗的数据
public class BattleContext
{
    public string regionId;           // 区域ID（影响地形）
    public string nodeType;           // 节点类型（普通/精英/Boss）
    public List<CharacterData> party; // 玩家队伍
    public int enemyLevel;            // 敌人等级
    public string enemyGroupId;       // 敌人群组ID
}
```

### 战斗后返回数据

```csharp
// 从战斗返回到地图的数据
public class BattleResult
{
    public bool isVictory;            // 是否胜利
    public int goldEarned;            // 获得金币
    public List<ItemData> loot;       // 掉落物品
    public List<CharacterData> party; // 更新后的队伍状态（HP/MP）
}
```

### 区域主题影响战斗

**森林区域**:
- 地形生成时增加"树木"地形比例
- 某些敌人获得"森林适应"Buff（闪避+10%）

**城堡区域**:
- 地形生成时增加"城墙"地形比例
- 精英敌人概率增加

**Boss领地**:
- 地形生成时增加"黑暗"地形比例
- Boss有独特机制

## 实现规划

### 第一阶段: 基础框架 (2-3周)

1. **区域系统**
   - 创建 `RoguelikeRegion` ScriptableObject
   - 修改 `RoguelikeMapGenerator` 支持区域生成
   - 实现区域切换逻辑

2. **节点状态系统**
   - 为 `RoguelikeMapNode` 添加 isRevealed/isVisited/isAccessible
   - 实现逐步揭示逻辑
   - 修改UI显示不同状态

3. **非战斗节点基础**
   - Store: 基础商店UI和购买逻辑
   - Treasure: 奖励发放逻辑
   - RestSite: 休息选项UI和效果

### 第二阶段: 事件系统 (2-3周)

1. **事件数据层**
   - 创建 `RoguelikeEvent` ScriptableObject
   - 设计事件数据表结构
   - 实现事件条件判定系统

2. **事件UI**
   - 事件弹窗UI
   - 选项按钮和条件显示
   - 结果展示

3. **基础事件内容**
   - 每个区域5-10个基础事件
   - 覆盖奖励/风险/条件/连锁类型

### 第三阶段: 区域主题和过渡 (1-2周)

1. **区域主题影响**
   - 区域影响战斗地形生成
   - 区域影响敌人配置
   - 区域影响事件池

2. **区域过渡事件**
   - 过渡事件UI
   - 过渡选择影响下一区域
   - 区域完成奖励

### 第四阶段: 内容填充和平衡 (持续)

1. **事件内容扩展**
   - 每个区域15-20个事件
   - 事件连锁和隐藏事件

2. **数值平衡**
   - 金币收入/消耗平衡
   - 敌人难度曲线
   - 奖励价值评估

3. **商店商品配置**
   - 商品池设计
   - 价格平衡
   - 稀有度分布

## 风险评估

### 技术风险
| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 事件系统复杂度 | 中 | 先实现基础框架，再逐步扩展 |
| 与现有代码兼容 | 低 | 扩展现有类，不重构核心逻辑 |
| 数据配置量 | 中 | 使用ScriptableObject，便于策划配置 |

### 内容风险
| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 事件数量不足 | 高 | 优先实现20个高质量事件，再扩展 |
| 数值平衡 | 中 | 早期频繁测试，快速迭代 |
| 重复感 | 中 | 事件随机化，区域主题差异化 |

### 体验风险
| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 无压力导致无聊 | 中 | 通过事件风险和奖励驱动探索 |
| 选择无意义 | 低 | 确保每个选择有明确后果 |
| 失败挫败感 | 中 | 提供失败总结和下次建议 |
