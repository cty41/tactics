## TL;DR

参考 FTL: Faster Than Light 的信标地图系统，实现自由探索的非线性地图生成方案。核心特征：有限视野迷雾、距离约束的网状连接、网格单元布局、BFS 连通性验证。取代了 v2.0 的层级推进模型。

---

## 设计目标

参考 FTL: Faster Than Light 的信标地图系统，实现以下核心体验：

- **自由探索**：玩家可重复往返已访问节点，不再线性推进
- **有限视野**：只能看到当前节点的连接邻居 + 已访问节点
- **路线规划**：每次生成独特的节点集群配置（密集网状或稀疏蜿蜒）
- **无死路**：所有路径都能通往 Boss，但选择不同路线有不同风险/收益

## 核心规则

### 1. 网格布局（Grid-Based Layout）

地图划分为 m×n 个正方形网格单元，每个网格单元内放置一个节点，节点位置在单元区域内随机。

- 起始点固定在最左侧列的某个单元
- Boss 终点固定在最右侧列的某个单元
- 网格单元尺寸 = 地图区域 / (m × n)
- 节点在单元内随机偏移，保证不与边界重合

### 2. 连接规则（Jump Lines）

**前向连接（主要）**：
- 每个节点连接相邻列（右侧）中距离 ≤ 最大可达距离的节点
- 优先连接距离更近的节点
- 保证玩家始终有前进路线

**侧向/后向连接（补充）**：
- 连接数不足 2 的节点，补连最近的可达节点
- 额外 20% 随机后向连接，形成 FTL 风格的网状结构
- 允许玩家"回头"探索已跳过的节点

### 3. 约束条件

| 约束 | 说明 |
|------|------|
| 最小节点间距 | 任意两节点距离 ≥ 配置值（防止重叠） |
| 商店间距 | 商店节点周围一定范围内不能有另一个商店 |
| 每节点最少 2 连接 | 保证无孤立节点 |
| BFS 连通性 | 从起点出发必须可达所有节点 |

### 4. 视野系统

- **已访问节点**：永久可见，显示完整信息
- **当前节点的连接邻居**：可见（Reachable 状态）
- **视野范围内的未访问节点**：可见但不可交互（Revealed 状态）
- **视野范围外的未访问节点**：不可见（Unrevealed 状态）

视野范围基于距离值计算，从当前节点沿连接路径遍历，路径距离 ≤ 视野范围的节点可见。

### 5. 生成参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| gridColumns | 5 | 网格列数 |
| gridRows | 4 | 网格行数 |
| nodeCount | 20 | 节点总数（= gridColumns × gridRows） |
| maxReachableDistance | 3.0 | 最大可达距离（欧几里得） |
| visionRange | 5.0 | 视野范围距离 |
| minDistanceBetweenNodes | 1.0 | 节点间最小距离 |
| storeMinDistance | 2.0 | 商店间最小距离 |

### 6. 验证与重试

生成后必须通过以下验证：
- 从起点 BFS 可达所有节点
- 每个节点至少有 2 个连接
- Boss 节点必须可达

验证失败则重新生成，最多重试 50 次。

## 视觉表现

参考 FTL 地图风格：
- 节点显示为圆点，已访问节点显示完整图标
- 当前节点到可达节点之间有虚线连接
- 不可达节点之间不显示连线
- Unrevealed 节点只显示空圆点（无图标信息）

## 与 v2.0 的差异

| 项目 | v2.0（层级模型） | v3.0（FTL 风格） |
|------|-----------------|------------------|
| 节点布局 | 按层排列（Layer 概念） | 网格布局（m×n单元，随机位置） |
| 路径模型 | 单向推进 | 可重复往返 |
| 连接规则 | 层间固定连接 | 距离约束 + 前向/后向混合 |
| 视野 | 全图可见 | 有限视野 + 迷雾 |
| 坐标系统 | Vector2Int(x, 层) | Vector2(网格单元内随机坐标) |
| 存档 | PlayerPrefs JSON | 暂时禁用（原型阶段） |
