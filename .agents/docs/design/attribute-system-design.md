# 属性系统设计文档

## 概述

本文档定义了Tactics项目中七维属性（Strength/Agility/Constitution/Speed/Intelligence/Charisma/Luck）在战斗中的具体作用机制。

## 属性基准值

所有属性的**中性值为5**。当属性等于5时，不产生额外加成或减益。

## 一级属性（七维属性）

### Strength（力量）

**作用对象**：近战单位（Barbarian等）

**战斗效果**：
- **近战普攻伤害**：每点超过5点，+1伤害；每点低于5点，-1伤害
- **近战技能伤害**：每2点超过5点，+1伤害；每2点低于5点，-1伤害

**公式**：
```csharp
// 近战普攻加成
meleeBasicBonus = Strength - 5;

// 近战技能加成
meleeAbilityBonus = Mathf.FloorToInt((Strength - 5) / 2f);
```

**设计意图**：
- 让力量成为近战核心属性
- 区分普攻和技能的加成效率，鼓励混合使用

---

### Agility（敏捷）

**作用对象**：远程单位（Hunter等）

**战斗效果**：
- **远程攻击/技能伤害**：每2点超过5点，+1伤害；每2点低于5点，-1伤害
- **闪避率**：提供闪避几率（见二级属性-闪避率）

**公式**：
```csharp
// 远程伤害加成
rangedBonus = Mathf.FloorToInt((Agility - 5) / 2f);
```

**设计意图**：
- 让敏捷成为远程核心属性
- 与力量形成近战/远程的清晰分工

---

### Constitution（体质）

**作用对象**：所有单位

**战斗效果**：
- **最大HP**：`MaxHP = Constitution × 4`，最低为1（当CON ≤ 0时）
- **战后恢复**：战斗结束后恢复 `Constitution × 2` HP
- **昏迷状态**：当HP < 0时，单位进入昏迷状态（Downed）

**公式**：
```csharp
// 最大HP
maxHealth = Mathf.Max(Constitution * 4, 1);

// 战后恢复
postBattleRegen = Constitution * 2;
```

**昏迷状态规则**：
- **触发条件**：HP < 0（严格小于0）
- **效果**：
  - 无法行动（跳过回合）
  - 无法被选中为攻击目标（可以被治疗）
  - UI显示昏迷标识
- **恢复**：
  - 战后自动恢复至至少1HP，脱离昏迷
  - 战斗中可通过治疗技能恢复至HP ≥ 0

**设计意图**：
- 体质是生存基础，影响所有单位的耐久度
- 战后恢复鼓励在Roguelike地图中推进而非频繁回城
- 昏迷状态增加战斗紧张感，避免"死血反杀"

---

### Speed（速度）

**作用对象**：所有单位

**战斗效果**：
- **移动力**：`MoveRange = max(1, Speed)`
- **先攻值**：`Initiative = Speed × 2`，决定回合中的先后次序
- **回合顺序**：先攻值越高，回合越早
- **敌人移动力**：使用配置值，不受Speed影响

**公式**：
```csharp
// 玩家移动力
moveRange = Mathf.Max(1, Speed);

// 先攻值
initiative = Speed * 2;

// 敌人移动力（由配置决定）
enemyMoveRange = configuredValue;
```

**设计意图**：
- 速度影响机动性，让高速单位可以更快到达关键位置
- 与先攻值结合，形成完整的"速度优势"
- 敌人使用配置值，便于关卡设计控制

---

### Intelligence（智力）

**作用对象**：施法单位（Mage等）

**战斗效果**：
- **法力恢复**：每回合结束时恢复 `floor(INT / 2)` 法力值
- **条件**：INT ≤ 0时，无法力恢复

**公式**：
```csharp
// 每回合法力恢复
manaRegenPerTurn = Mathf.Max(Mathf.FloorToInt(Intelligence / 2f), 0);
```

**设计意图**：
- 智力是施法续航的关键
- 低智力单位无法持续使用技能

---

### Charisma（魅力）

**作用对象**：所有单位

**战斗效果**：
- **最大法力值**：`MaxMana = Charisma × 3`
- **初始法力值**：战斗开始时拥有 `Charisma` 点法力值

**公式**：
```csharp
// 最大法力值
maxMana = Charisma * 3;

// 初始法力值
initialMana = Charisma;
```

**设计意图**：
- 魅力决定法力池大小，影响技能使用频率
- 初始法力值等于Charisma，低魅力单位战斗开始时法力很少
- 与智力配合：魅力决定"容量"，智力决定"恢复速度"

---

### Luck（幸运）

**作用对象**：所有单位

**战斗效果**：
- **暴击率**：基础10%，每点Luck+2%
- **额外骰子**：每偏离基准5点，±1个骰子

**公式**：
```csharp
// 基础暴击率
baseCritChance = 0.10f;

// 实际暴击率
critChance = baseCritChance + (Luck - 5) * 0.02f;

// 额外骰子数（高幸运取最好，低幸运取最差）
extraDice = Mathf.FloorToInt(Mathf.Abs(Luck - 5) / 10f);
```

**骰子机制详解**：

当需要进行随机判定（如暴击、闪避等）时：

1. **正常情况**（Luck = 5）：
   - 投掷1个骰子，结果直接采用

2. **高幸运**（Luck > 5）：
   - 投掷 (1 + extraDice) 个骰子
   - 取所有骰子中的**最好结果**
   - 例如：Luck = 15，投掷2个骰子，取较高值

3. **低幸运**（Luck < 5）：
   - 投掷 (1 + extraDice) 个骰子
   - 取所有骰子中的**最差结果**
   - 例如：Luck = -5，投掷2个骰子，取较低值

**设计意图**：
- 幸运提供不稳定的爆发潜力（高幸运）或稳定的保守输出（低幸运）
- 额外骰子机制让幸运的影响非线性，高/低幸运都有显著差异

## 二级属性系统

### HP系统

**最大HP**：
```csharp
MaxHP = max(Constitution × 4, 1)
```

**当前HP规则**：
- 战斗开始时：HP = MaxHP
- 受到伤害：HP减少
- 受到治疗：HP增加，不超过MaxHP
- HP < 0：进入昏迷状态（Downed）
- HP = 0：仍可行动，但再受一次伤害会昏迷

**战后恢复**：
```csharp
恢复量 = Constitution × 2
```
- 恢复后HP不超过MaxHP
- 如果单位昏迷，恢复后至少为1HP，脱离昏迷

### MP系统

**最大MP**：
```csharp
MaxMana = Charisma × 3
```

**当前MP规则**：
- 战斗开始时：MP = Charisma（初始法力值）
- 使用技能：MP减少
- 每回合结束：MP恢复 `floor(INT / 2)`
- MP不超过MaxMana
- INT ≤ 0时，不恢复MP

**初始法力值设计**：
- 战斗开始时MP = Charisma
- 低魅力单位（如Barbarian）初始法力很少，需要积累
- 高魅力单位（如Mage）可以更快使用技能

### 先攻系统（Initiative）

**先攻值**：
```csharp
Initiative = Speed × 2
```

**作用**：
- 决定回合中的行动先后顺序
- 先攻值越高，行动越早
- 替代原有的纯Speed排序，提供更精细的控制

**实现要点**：
- 需要修改回合解析器
- 按先攻值降序排列单位行动顺序
- 先攻值相同时，可加入随机因子或单位ID打破平局

### 近战攻击范围（Reach）

**基础值**：
```csharp
BaseReach = 1
```

**作用**：
- 决定近战技能的攻击范围
- 默认值为1（相邻格子）
- 可通过武器装备增长

**增长方式**：
- 武器配置：某些武器提供 +1 或更多 Reach
- Buff效果：某些技能临时增加Reach
- 计算公式：`TotalReach = BaseReach + WeaponReachBonus + BuffReachBonus`

### 远程攻击范围（Range）

**基础值**：
```csharp
BaseRange = 由技能配置决定（如RangedAttack的maxRange=5）
```

**作用**：
- 决定远程技能的攻击范围
- 由技能配置决定基础值
- 可通过武器装备增长

**增长方式**：
- 武器配置：某些武器提供 +1 或更多 Range
- Buff效果：某些技能临时增加Range
- 计算公式：`TotalRange = BaseRange + WeaponRangeBonus + BuffRangeBonus`

### 闪避率系统（Dodge Chance）

**基础值**：
```csharp
BaseDodgeChance = 0f
```

**作用**：
- 决定单位闪避攻击的几率
- 遵循乘法叠加（Diminishing Returns）原则

**公式**：
```csharp
// 单个闪避事件的概率
dodgeEventChance = 由Agility、Buff、地形等决定

// 最终不被闪避的命中几率 = 所有闪避事件各自不触发的概率之积
finalHitChance = ∏(1 - dodgeEventChance_i)

// 最终闪避率
dodgeChance = 1 - finalHitChance
```

**示例**：
- 单位A有3个闪避来源：
  - 高Agility提供20%闪避
  - Buff提供15%闪避
  - 地形提供10%闪避
- 计算：
  - 不被闪避的概率 = (1-0.2) × (1-0.15) × (1-0.1) = 0.8 × 0.85 × 0.9 = 0.612
  - 最终闪避率 = 1 - 0.612 = 38.8%

**设计意图**：
- 避免闪避率直接相加导致100%闪避
- 多个闪避来源仍然有效，但收益递减
- 鼓励多样化构建而非堆叠单一属性

### 移动力系统

**玩家移动力**：
```csharp
MoveRange = max(1, Speed)
```

**敌人移动力**：
```csharp
MoveRange = configuredValue // 由AI配置或关卡设计决定
```

**规则**：
- Speed ≤ 0时，基础移动力为1
- BonusMovement来自装备、Buff等额外加成（未来扩展）
- 敌人不受Speed影响，便于关卡平衡

### 暴击率系统

**基础暴击率**：10%（Luck = 5时）

**实际暴击率**：
```csharp
critChance = 0.10f + (Luck - 5) * 0.02f
```

**额外骰子**：
```csharp
extraDice = floor(|Luck - 5| / 10)
```

**暴击伤害**：2倍伤害（已有实现）

## 属性与职业的对应关系

| 职业 | 核心属性 | 次要属性 | 战斗风格 |
|------|----------|----------|----------|
| **Barbarian** | Strength | Constitution | 高伤害近战，高耐久 |
| **Mage** | Intelligence | Charisma | 高法力池，持续施法 |
| **Hunter** | Agility | Speed | 高机动远程，先手优势 |

## 属性成长

### 升级奖励

- **每次升级获得1点属性点**，可自由分配
- 属性点分配是永久性的，影响所有后续战斗

### 装备加成

- 装备提供属性加成，影响战斗中的表现
- 装备加成在战斗开始时应用

### 事件选择

- 某些事件提供临时或永久属性调整
- 临时调整在战斗结束后消失

## 昏迷状态详细设计

### 状态定义

**Downed（昏迷）**：单位因受到过量伤害而无法行动的状态。

### 状态规则

1. **触发条件**：
   - HP < 0（严格小于0）
   - 注意：HP = 0时仍可行动

2. **状态效果**：
   - 无法执行任何行动（移动、攻击、使用技能）
   - 回合被跳过
   - 无法被选中为攻击目标（可以被治疗）
   - UI显示昏迷标识（如灰色头像、倒地动画）

3. **状态恢复**：
   - **战后恢复**：战斗结束后自动恢复至至少1HP，脱离昏迷
   - **战斗中治疗**：通过治疗技能或道具恢复至HP ≥ 0，脱离昏迷
   - **自然恢复**：某些Buff或地形可能提供每回合恢复

4. **特殊规则**（可选）：
   - **处决攻击**：昏迷单位受到攻击时可能受到额外伤害
   - **保护机制**：昏迷单位附近的友军可能获得防御加成
   - **救援机制**：友军可以花费行动点将昏迷单位拉起

### 实现要点

- 需要修改 `CombatComponent.ModifyHealth`，检测HP < 0时设置 `IsDowned = true`
- 需要修改回合解析器，跳过 `IsDowned = true` 的单位
- 需要添加UI状态显示

---

## 实现注意事项

1. **伤害计算顺序**：
   ```
   基础伤害 → 属性加成 → 暴击判定 → 防御减免 → 最终伤害 → HP修改 → 昏迷检测
   ```

2. **属性变化处理**：
   - 属性提升时，当前HP/MP不应超过新的MaxHP/MaxMana
   - 属性降低时，当前HP/MP需要截断至新的MaxHP/MaxMana
   - 如果CON降低导致MaxHP减少，当前HP可能需要相应减少

3. **存档兼容性**：
   - 如果修改了Unit的序列化字段，需要版本迁移
   - 建议通过 `PlayerAdventureState.Version` 字段处理

4. **性能考虑**：
   - 属性计算应在值变化时进行，而不是每帧计算
   - 缓存MaxHP、MaxMana、MoveRange等值，避免重复计算
