# Death Pose Deterministic Shaping 失败复盘

> Status: superseded。2026-08-20 的人工 Review 证明该方案虽能逼近参考角度和长宽比，却会破坏角色的连续轮廓；`render-death-recipe` 已从公开 CLI 移除，仅保留历史记录读取能力。

## 发生了什么

旧方案把核心、耳朵、手爪和脚爪按语义蒙版拆开，分别旋转、压缩和重投影，再把装备与 X 眼叠回。数值测量可以通过，但连接处出现裂缝、错层和碎片，整体观感明显劣于此前“先完整生成、成功后再提炼”的死亡图流程。

失败的根因不是容差不够精细，而是抽象边界错误：身体、耳朵和相连四爪共同构成一个连续软体轮廓，不能作为独立刚性零件整形。主轴角和压扁比只能成为生成与验收目标，不能成为成品修补算法。

## 保留规则

- 完整死亡姿态由身份母图和姿态参考共同生成，一次只迭代一个候选。
- 身体、耳朵和相连四爪必须保持单一连续轮廓；只有真正脱手的装备与限定眼区 X 眼可以独立合成。
- 参考图只提供屏幕方向、角度、紧凑度和尺寸比较目标，不迁移身份或职业结构。
- 成功候选先由用户人工确认，再提炼最小通用规则；不得在成功前扩展状态机能力。

## 正式替代流程

对已经由用户逐轮确认、但生成前没有状态机 invocation 的精确成图，使用 `reviewed_import`，不伪造 ImageGen 调用记录：

1. `render-size-comparison` 确定性生成 Identity、Previous、Pose reference、Candidate 四栏对比，并记录各自可见 AABB。
2. 用户明确确认尺寸与观感后，`adopt-reviewed-sprite` 绑定源图、256 候选、128 预览、对比图、审核人 `cty41`、原因和带时区时间戳。
3. `approve` 生成绑定全部哈希的 receipt，`promote` 原样复制候选和预览字节到正式路径。
4. `check --strict` 验证血缘、哈希、审批与正式 provenance。

魔剑士死亡图 Round v04 已按该路径晋升。旧 recipe、蒙版和失败 Review 继续作为历史证据保留，但不得作为新生成入口或规范依据。
