# 统一节点定义模板

## 状态

- 日期：2026-06-27
- 用途：作为 Roguelike / pure run 原型中的共享节点定义模板
- 关联文档：[短期原型 Task 1：核心循环与失败标准](./2026-06-24-short-term-prototype-task1-design.md)
- 关联文档：[纯 Run 三人小队原型设计](./2026-06-24-pure-run-squad-prototype-design.md)

## 一句话原则

节点首先是 `决策功能体`，其次才是 `内容容器`。

在原型阶段，节点定义不应先回答“这里能给什么”，而应先回答：

1. 它要迫使玩家回答什么问题
2. 它默认在劝玩家做什么
3. 它默认在劝退哪种选择
4. 如果玩家顺着原冲动继续走，会付出什么代价
5. 它会如何压缩、恢复或扩宽下一轮的合理解法集合

## 适用范围

这份模板同时服务两类文档：

1. `Task 1` 验证口径
   - 重点回答：`结算 -> 再选择` 是否成立
2. `pure run` 三人构筑口径
   - 重点回答：小队构筑是否真正进入地图决策层

因此，同一个节点模板既要能表达：

- 它是否改变路线选择
- 它是否改变资源分配
- 它是否改变风险偏好
- 它是否改变三人职责重配

## 统一判据

一条路线或节点选择，只有在同时满足以下两个条件时，才应被视为当前 run 中的合理选择：

1. 该选择在结算后，不会将当前小队压缩到仅剩单一、被迫的后续解法；玩家在进入下一轮决策时，仍应保有至少两种可成立的推进方案。
2. 该选择所带来的结算结果，应能够修复当前痛点、放大既有优势，或使原本边缘的后续方案转化为可行方案，从而真实改变下一轮的路线、补给、资源分配或风险偏好判断。

可进一步压成两句工作定义：

- `能承受`：走完这条路线后，下一轮仍保有至少两种合理解法，而不是只剩单一路径求生。
- `值得去`：这条路线的结果，能让下一轮出现新的合理解法，或让原本边缘的解法变成可行解法。

## 最小模板

以下字段为必填项，优先保证节点能被写成“对当前痛点的取舍题”。

```md
## 节点名
- 决策职责：让玩家在______与______之间做判断
- 首要服务对象：
- 默认劝玩家做什么：
- 默认劝退哪种选择：
- 对抗的玩家冲动：
- 顺着冲动走下去的代价：
- 对下一轮解法集合的作用：
```

## 必填字段说明

### 1. 决策职责

必须直接写成一道题，而不是奖励清单。

正确方向：

- 让玩家在“先修复当前损伤”与“继续贪高收益路线”之间做判断
- 让玩家在“补当前短板”与“放大已有优势”之间做判断

错误方向：

- 这里可以回血、给药、给钱、掉装备

### 2. 首要服务对象

明确这个节点默认主要服务哪类局面，而不是想服务所有状态。

常见对象：

- 状态受损的小队
- 资源紧张的小队
- 已初步成型、想滚雪球的小队
- 需要把金币转化成当前稳定性的队伍

### 3. 默认劝玩家做什么

写清它想把玩家往哪边推，例如：

- 先修复再推进
- 先转资源再冒险
- 趁 build 成型主动升风险

### 4. 默认劝退哪种选择

写清它天然在压哪种错误倾向，例如：

- 残状态下继续无脑连战
- 一味死攒金币不转化
- 拿到成长后仍然机械保守

### 5. 对抗的玩家冲动

这里写的是“人会忍不住做的错事”，而不是理性目标。

常见冲动：

- 见收益就拿
- 残血硬顶
- 拿到成长就过度激进
- 资源紧张却继续拖着不用

### 6. 顺着冲动走下去的代价

代价不要写成抽象的“亏”，而要优先写成：

- 后续合理路线被压缩
- 只能被迫找补给
- 小队分工失衡
- 无法承受高价值路线
- 当前优势无法转成后续主动权

### 7. 对下一轮解法集合的作用

至少写清楚它更偏哪一种：

- 主要扩宽
- 有条件扩宽
- 主要压缩
- 有条件压缩

并补一句说明：

- 它通过恢复什么、转化什么、放大什么，来改变下一轮的合理选择数量或质量

## 可选字段

当节点设计进入第二轮细化时，再补以下字段：

```md
- 主要作用资源：
- 风险/门槛：
- 反馈信号：
- 与其他节点的互补关系：
```

### 主要作用资源

推荐从以下四类里选主项：

- `HP / MP / 死亡状态`
- `消耗品变化`
- `技能 / 天赋 / 属性成长`
- `金币 / 商店机会`

必要时再补：

- `装备配置`
- `小队职责分配`

### 风险/门槛

用于描述：

- 进入成本
- 绕路成本
- 机会成本
- 结果波动性

### 反馈信号

用于检查节点是否真的改变了解题方式。推荐写成玩家结算后能立刻说出的一句话。

例如：

- “这下我可以继续走中风险路线了。”
- “这次成长后，我们可以主动去打高价值点了。”
- “这波钱必须先转成稳定性，不能继续捏着。”

### 与其他节点的互补关系

用于避免节点孤立定义。

例如：

- 补给点通常作为高压战斗后的修复点
- 成长点通常作为风险升级前的放大点
- 商店点通常作为经济转稳健性的转化点

## 示例一：补给点

```md
## 补给点
- 决策职责：让玩家在“立即修复当前损伤”与“保留资源继续贪收益路线”之间做判断
- 首要服务对象：HP、MP 或整体生存状态已经受压的小队
- 默认劝玩家做什么：先修复关键短板，恢复继续推进资格
- 默认劝退哪种选择：残状态下继续无脑连战
- 对抗的玩家冲动：觉得“还能撑”，因此硬顶后续高压节点
- 顺着冲动走下去的代价：后续合理路线被压缩，只剩低容错或被迫补救的单一路径
- 对下一轮解法集合的作用：主要扩宽；通过恢复 HP、补充 MP 或缓解死亡风险，让玩家重新拥有至少两种说得通的推进方案
```

## 示例二：成长点

```md
## 成长点
- 决策职责：让玩家在“补当前短板”与“放大已有优势”之间做判断
- 首要服务对象：已有初步分工、但尚未完全成型的小队
- 默认劝玩家做什么：围绕当前三人职责做一次明确强化或重配
- 默认劝退哪种选择：把成长当成泛用数值增强，不改变打法
- 对抗的玩家冲动：见到成长就无脑拿最通用加成，不考虑小队协同
- 顺着冲动走下去的代价：角色各自变强但小队不成型，后续高价值路线无法稳定承接
- 对下一轮解法集合的作用：有条件扩宽；若成长能明确改变职责分配、技能联动或装备优先级，则会扩宽路线与风险选择，否则只是表面增强
```

## 用法建议

在原型阶段，先要求每一种节点类型都必须能回答以下检查问题：

1. 它默认在修哪个痛点，或放大哪种优势？
2. 它默认在劝玩家做什么，又在劝退什么？
3. 如果玩家无视它，下一轮会损失什么解法空间？
4. 走完这个点之后，玩家是否仍保有至少两种合理推进方案？
5. 它是否会让某种原本边缘的路线或小队配置变得可行？

如果答不上来，这个节点大概率仍然是“内容容器”，而不是“决策功能体”。
