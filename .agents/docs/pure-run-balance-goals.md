# Pure Run 原型平衡目标

更新时间：2026-07-31。本文是 Pure Run 数值调优的体验目标与停止条件；当前实现真值见 [当前战斗数值](pure-run-current-combat-values.md)，外部参考带见 [Mewgenics 归一化基准](pure-run-mewgenics-benchmark.md)。

## 原型定位与目标受众

Pure Run 是一局内完成的固定三人小队短流程：玩家用有限路线、战斗、恢复与成长选择形成一条可复盘的构筑轨迹。P0 面向熟悉回合制/战棋基础操作、但不要求预先掌握本项目技能细节的玩家；不是为已经记住敌人 Pattern 的高手设定最终难度。

首次或近首次体验应允许玩家在普通战中理解集火、站位、资源与职业循环，在精英战承受阵型或机制压力，并在 Boss 前后遇到至少一次需要改变原计划的战术转折。失败应主要发生在中后段精英或 Boss，而不是前三场普通战；失败应能归因于选择与资源管理，而非软锁、不可读规则或随机数值尖峰。

**允许减员通关。** 一名角色在中后段倒下后仍可完成 run 属于可接受的高代价胜利；但不以“必须牺牲一人”为标准策略，也不接受前三场普通战经常减员。全员无损不应成为唯一稳定解。

## 绿 / 黄 / 红原型指标

以下阈值是后续固定 seed、自动化遥测与小样本试玩要验证的**原型假设**，不是已完成试玩结论，也不是最终发行承诺。

| 指标 | 绿 | 黄 | 红 |
|---|---|---|---|
| 技术可完成性 | 10/10 固定 seed 无软锁、AI 停摆或状态损坏 | 9/10，问题可复现且可绕过 | ≤8/10 或阻塞主流程 |
| 前三场普通战胜率 | 80%–95% | 60%–79%，或 96%–100% 且几乎无损 | <60% |
| 首次/近首次完整 run 通关率 | 30%–60% | 15%–29% 或 61%–80% | <15% 或 >80% |
| 普通战长度 | 多数 3–5 个完整轮次 | 多数 2 或 6–7 轮 | 经常 1 轮或 >7 轮 |
| 精英战长度 | 多数 4–7 轮 | 多数 3 或 8–9 轮 | 经常 <3 或 >9 轮 |
| Boss 战长度 | 多数 5–8 轮，至少一次战术转折 | 3–4 或 9–10 轮 | <3 或 >10 轮 |
| 有意义选择 | ≥70% 战斗 `meaningful_choice_score >= 3`，即至少一次非显然选择 | 50%–69% | <50% |
| 可读性主观评分 | 平均 ≥4/5 | 3.0–3.9 | <3.0 |
| 技能支配性 | 最高单一非基础 `skill_id` 占成功且改变状态的非普攻施放 `≤65%` | `>65%` 且 `≤80%` | `>80%` |
| 跨战资源压力 | Rest、药水或资源保留至少一项影响路线，但不成为必选 | 压力偶发或偏强 | 完全无压力，或早期不可恢复 |
| 减员位置 | 偶发于精英/Boss，仍有可执行残局 | 中段已有明显减员但可归因 | 前三战频繁减员，或减员后必然软失败 |

统计时必须同时保留 seed、路线、成长选择、配方、Special 实际变体、完整轮次、倒地位置和恢复前后 HP/MP；没有这些上下文的单一胜率不能直接触发数值修改。完整 run 通关率按 `build_id + tester + run_seed` 去重后的 `run_result` 计算，不得拿最后一场的战斗 `result` 代替。选择比例只使用有评分的战斗并报告覆盖率；技能支配性必须按 `skill_id` 汇总，成功非普攻施放总数少于 10 时标为样本不足，不判灯色。

## P0 只读范围

P0-B 只建立可验证基线：

- 从 Unity 当前真实类型、Ability/SkillGraph、正式怪物 Prefab、Brain/Profile/Pattern 与 EncounterCatalog 只读导出；
- 修正文档冲突，并把未知项明确标成未验证；
- 固化 Mewgenics 的聚合参考与归一化公式；
- 允许运行只读 report、validator 和测试；
- **不修改 C#、Unity 资产、游戏数值、场景或存档，不提交。收口时只允许同步本任务命中的 `project-documentation` OKF scope，不同步由用户既有改动触发的其他 scope。**

P0 不声称完成手动试玩，也不根据一次导出直接判断“强/弱”。进入调优前，应先用固定 seed 和同路线采样建立当前基线，再一次只改一个杠杆。

## Current-pool baseline 的局限

当前 `N1–N6`、`E1–E2`、`Special` 是显式配方池，不是按层动态威胁预算。它适合做**当前池基线**，但不能单独证明完整 run 的难度曲线：

- 普通配方为 3 或 4 个实体，但组合技能、出生布局和 AI 风格不同；同头数不等威胁；
- E1/E2 复用普通组合并应用生命/输出倍率；倍率不等于额外行动或新机制；
- Special 是单一精英实体，已有 Pattern，但当前导出未证明额外行动、阶段或召唤；Boss 评价必须看有效行动预算；
- 角色起始分支由 seed 决定，后续成长、路线服务节点和掉落会改变每场可用资源；
- `MaxUsesPerTurn = 0` 表示能力资产本身不限成功次数，不等于战斗中没有行动、目标、长矛或资源约束；
- 自动化正确性测试不等于手感、可读性和首次玩家胜率。

因此首轮结论只能是“当前池在现有实现下的可测基线”，不能把它写成最终分层或最终平衡答案。
