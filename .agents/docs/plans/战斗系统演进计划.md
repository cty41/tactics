# 战斗系统分析与演进计划

## Background

### 当前战斗系统现状

项目采用**外围 Roguelike + 局内战棋**的架构，战斗系统已具备以下基础：

| 模块 | 现状 | 健康度 |
|------|------|--------|
| **战斗生命周期** | `BattleController` → `GridController` → 状态机驱动，支持开始/回合/结束/返回 RoguelikeMap | ✅ 成熟 |
| **回合制** | 基于 `Speed` 的 `SubsequentTurnResolver`，每方轮流行动所有单位 | ✅ 可用 |
| **单位模型** | `Unit`/`TilemapUnit` 包含六维属性（力量/敏捷/体质/智力/魅力/运气）、HP/MP/移动力 | ✅ 可用 |
| **技能系统** | `AbilityConfig`（ScriptableObject）+ `AbilityEffect` 列表，数据驱动配置 | ⚠️ 框架完整，效果未全部实现 |
| **职业系统** | `RoleConfig` + `RoleType` 枚举（Barbarian/Mage/Hunter），含技能列表 | ⚠️ 仅做分类，无职业机制差异化 |
| **Buff 系统** | `BuffComponent` + `Buff` 基类，有 `IgniteBuff` 示例 | ⚠️ 框架完整，ApplyBuffEffect/DoT 未接入 |
| **战斗公式** | 简单直接：伤害 = (AttackFactor + 属性加成) × 暴击 − DefenceFactor | ⚠️ 深度不足 |
| **AI 系统** | `AIPlayer` + `BehaviourTree` 行为树，支持自定义节点 | ✅ 可用 |
| **Roguelike 桥接** | `BattlePartyBootstrap` 从 `PlayerAdventureState` 加载队伍，`CharacterStatsApplicator` 应用属性 | ⚠️ 只传基础属性，无装备/天赋/HP 持久化 |
| **战斗结算** | `RoguelikeBattleReturnHandler` 仅更新地图路径，无奖励/掉落 | ❌ 缺失 |

### 核心问题

1. **构筑与战斗断层**：Roguelike 外围只有角色等级和基础属性，没有装备、天赋、技能选择等"构筑"要素，导致进入战斗后缺乏"我之前的选择带来了什么"的反馈。
2. **职业同质化**：Barbarian/Mage/Hunter 的区别仅在于技能列表，没有职业核心机制（如怒气/元素充能/标记）。
3. **技能效果待实现**：`ApplyBuffEffect`、`DamageOverTimeEffect`、`KnockbackEffect` 均为 TODO，实际战斗中只有伤害/治疗/移动。
4. **战斗后无奖励**：胜利后仅推进地图节点，没有战利品、金币、事件选择等 Roguelike 核心循环。
5. **战斗体验单调**：无地形交互、无范围技能（AOE）、无连携机制，每回合决策空间小。

### 目标

在保持现有架构稳定的前提下，以**"构筑→表达→反馈"**为核心循环，将 Roguelike 外围的构筑选择有效传递到局内战棋中，同时扩展战斗内的策略深度。

### 预期收益

- 每次 Roguelike 节点选择（战斗/商店/休息）都能显著影响下一场战斗的体验。
- 三个职业具有截然不同的战斗节奏和核心机制。
- 战斗胜利后有明确的奖励反馈，强化"再开一局"的动机。

## Scope

### In Scope

1. **装备系统数据层 + 战斗接入**：为 `CharacterDefinition` 添加装备槽，在 `BattlePartyBootstrap` 中将装备属性应用到 `Unit`。
2. **职业技能差异化（第一版）**：为三个职业设计并实现独特的战斗资源/机制。
3. **战斗结算与奖励系统**：战斗胜利后生成奖励（金币/装备/技能/属性），返回 RoguelikeMap 时持久化。
4. **Buff/DoT/击退效果落地**：让 `AbilityConfig` 中已有的这些效果类型真正在战斗中生效。
5. **范围技能与连锁技能**：新增 `AreaEffect`（AOE）和 `ChainEffect`（连锁跳跃）两种效果类型。
6. **地形效果（基础版）**：为 `Cell` 添加地形类型，影响移动消耗和战斗伤害。
7. **战斗反馈优化**：伤害数字飘字、暴击/Miss 提示、战斗日志 UI 展示。

### Out of Scope

- 不重构回合解析器（`SubsequentTurnResolver` 的回合顺序逻辑保持不变）。
- 不实现完整的多人网络同步（网络相关代码保持现状）。
- 不新增敌人类型或 Boss AI（使用现有行为树机制配置即可）。
- 不开发局外天赋树 UI（仅提供数据层接口，UI 后续迭代）。
- 不改动寻路算法（A* / Dijkstra 保持现状）。

---

## Assumptions

1. **允许扩展 `CharacterDefinition`**：需要新增装备槽字段（如 `Equipment` 字典或列表）。
2. **允许扩展 `Unit` 属性**：需要为职业机制新增运行时资源字段（如 `Rage`、`MarkStacks`），这些字段不影响现有序列化。
3. **允许扩展 `AbilityEffect` 子类**：在现有 `AbilityEffect` 继承体系下新增 `AreaEffect`、`ChainEffect` 等。
4. **允许修改 `CombatComponent`**：需要在伤害计算中接入 Buff、地形、职业机制等加成。
5. **允许修改 `RoguelikeBattleReturnHandler`**：需要在战斗结束后插入奖励结算逻辑。
6. **RoguelikeMap 的商店/休息站节点后续开发**：本次计划只提供战斗结算奖励，商店购买和休息治疗的逻辑在后续迭代中实现。
7. **美术资源由外部提供**：本次计划只涉及代码和配置，不制作新的技能特效、图标或模型。

## Tasks

### Phase 1: 构筑→表达闭环（核心连接）

#### Task 1: 装备系统数据层与战斗接入
- **目标**：让 Roguelike 外围的装备选择能在局内战斗中体现为属性加成或机制变化。
- **输入**：`CharacterDefinition`（当前无装备字段）、`CharacterStatsApplicator`（只传六维属性）。
- **输出**：
  - `CharacterDefinition` 新增 `Equipment` 集合（如 `Dictionary<EquipmentSlot, EquipmentItem>`）。
  - `EquipmentItem` 数据模型（名称、属性加成、特效 ID、图标）。
  - `CharacterStatsApplicator.ApplyToUnit` 在应用基础属性后，追加装备属性加成。
  - `BattlePartyBootstrap` 从 `PlayerAdventureState` 读取装备并传递给 `CharacterStatsApplicator`。
- **验收标准**：
  - 给角色装备一件 +5 力量的武器后，战斗中该 `Unit.Strength` 比基础值高 5。
  - 卸下装备后，下一场战斗属性恢复正常。
- **⚠️ 核心代码改动**：`CharacterDefinition`（新增字段）、`CharacterStatsApplicator`（修改逻辑）。

#### Task 2: 职业技能差异化（第一版）
- **目标**：让 Barbarian/Mage/Hunter 在战斗中拥有截然不同的核心机制和资源循环。
- **输入**：现有的 `RoleType` 枚举和 `RoleConfig`。
- **输出**：
  - **Barbarian（狂战士）**：`Rage` 资源。受伤和造成伤害时积累怒气，怒气提升伤害减免和暴击率，可消耗怒气释放强化技能。
  - **Mage（法师）**：`ElementalCharge` 元素充能。施放技能时积累对应元素层数，同元素叠加增益，不同元素组合触发反应（如火+风 = 扩散范围伤害）。
  - **Hunter（猎人）**：`Mark` 标记。技能和攻击对目标施加标记，被标记目标受到的伤害提升，猎人攻击标记目标时恢复移动力或获得额外行动。
  - `Unit` 新增职业资源字段（如 `ClassResource` 结构体）。
  - `CombatComponent` 在伤害计算和受击时调用职业资源更新逻辑。
  - 为每个职业配置 1-2 个体现职业机制的新技能（ScriptableObject）。
- **验收标准**：
  - 同一关卡中，Barbarian 越战越勇（低血量高输出），Mage 需要规划元素组合顺序，Hunter 需要优先集火标记目标。
  - 职业资源在 UI 上有可视化显示（Battle UI 状态面板扩展）。
- **⚠️ 核心代码改动**：`Unit`（新增资源字段）、`CombatComponent`（修改计算流程）、`AbilityEffect`（新增职业相关效果）。

#### Task 3: 战斗结算与 Roguelike 奖励桥接
- **目标**：战斗胜利后返回地图时，玩家获得可感知的奖励，强化 Roguelike 循环。
- **输入**：`RoguelikeBattleReturnHandler`（当前只更新路径）、`BattleFlowCoordinator.EndBattleAsync`。
- **输出**：
  - `BattleRewardSystem`：根据战斗难度（普通/精英/Boss）生成奖励池。
  - 奖励类型：金币、装备（随机稀有度）、属性提升（永久+1 力量等）、技能书（学习/替换技能）。
  - 胜利后弹出奖励选择界面（3 选 1）。
  - 选择结果写入 `PlayerAdventureState`，持久化到 `PlayerPrefs`。
  - 返回 RoguelikeMap 后，金币和队伍状态同步到地图 HUD。
- **验收标准**：
  - 击败 Boss 后必出稀有装备选择；击败普通敌人后获得金币或小属性提升。
  - 选择奖励后，下一场战斗中能立即感受到变化（如装备加成生效、新技能可用）。
- **⚠️ 核心代码改动**：`RoguelikeBattleReturnHandler`（插入结算逻辑）、`PlayerAdventureState`（新增奖励相关字段）。

### Phase 2: 技能与战斗深度

#### Task 4: Buff、DoT 与击退效果落地
- **目标**：让 `AbilityConfig` 中已有的 `ApplyBuffEffect`、`DamageOverTimeEffect`、`KnockbackEffect` 真正生效。
- **输入**：现有 `AbilityEffect` 子类的 TODO 实现。
- **输出**：
  - `ApplyBuffEffect.Execute`：根据 `_buffType` 创建对应的 `Buff` 实例（如 `IgniteBuff`），通过 `target.AddBuff()` 施加。
  - `DamageOverTimeEffect.Execute`：创建持续伤害 Buff（如 `PoisonBuff`，每回合开始时扣血）。
  - `KnockbackEffect.Execute`：计算击退方向，调用 `MoveComponent` 将目标沿直线推离 `_distance` 格，若撞到障碍物则额外受伤。
  - 为已有技能配置添加 Buff/DoT/击退效果示例（如 Mage 的火球术附加点燃，Barbarian 的重击附加击退）。
- **验收标准**：
  - 施加点燃后，目标每回合开始时受到 DoT 伤害，持续 3 回合。
  - 击退效果将敌人推到悬崖/障碍物时有额外反馈（伤害或眩晕）。
- **⚠️ 核心代码改动**：`ApplyBuffEffect`、`DamageOverTimeEffect`、`KnockbackEffect`（补完实现）；`MoveComponent`（可能需新增强制位移接口）。

#### Task 5: 范围技能与连锁技能
- **目标**：扩展技能的表现形式，增加战场上的位置策略价值。
- **输入**：现有的 `TargetingStrategy` 和 `AbilityEffect` 体系。
- **输出**：
  - `AreaEffect`：以目标点为中心，对半径内所有敌人/友方生效。可配置友军伤害开关、边缘衰减。
  - `ChainEffect`：对首要目标造成伤害后，自动跳跃到附近最近的目标（最多 N 次），每次跳跃伤害递减。
  - 对应的 `TargetingStrategy` 扩展：点选地面（Area）、点选敌人（Chain）。
  - 为 Mage 配置火球术（Area），为 Hunter 配置闪电箭（Chain）。
- **验收标准**：
  - 火球术点选地面后，爆炸范围内所有单位（含友军）受到伤害。
  - 闪电箭命中第一个敌人后，自动跳跃到 2 格内的另一个敌人，伤害每次衰减 25%。
- **⚠️ 核心代码改动**：新增 `AreaEffect`、`ChainEffect` 类；扩展 `TargetingStrategy`（不破坏已有策略）。

#### Task 6: 地形效果（基础版）
- **目标**：让战场地形成为策略决策的一部分。
- **输入**：现有的 `Cell` / `ICell` 接口、`Tilemap` 系统。
- **输出**：
  - `Cell` 新增 `TerrainType` 枚举（平地/草地/水面/火焰/高地/沼泽）。
  - 地形影响：
    - **水面**：移动力消耗 +1，火焰技能命中后产生蒸汽（遮挡视野一回合）。
    - **火焰地表**：每回合开始时对站立单位造成小额伤害；水系技能可熄灭。
    - **高地**：攻击低地目标时伤害 +20%，被低地攻击时伤害 -10%。
    - **沼泽**：移动力消耗翻倍，有概率被困住（本回合无法移动）。
  - `CombatComponent` 和 `MoveComponent` 在计算时读取当前格子的 `TerrainType`。
  - `UnityCellManager` 从 `DataLayer` Tilemap 读取地形数据并初始化 `Cell.TerrainType`。
- **验收标准**：
  - 单位站在火焰地表上时，每回合开始自动扣血。
  - 高地单位攻击低地单位时，伤害数字比平常高 20%。
- **⚠️ 核心代码改动**：`Cell`/`ICell`（新增 TerrainType 字段）、`CombatComponent`（地形加成）、`MoveComponent`（地形移动力）。

### Phase 3: 体验优化

#### Task 7: 战斗反馈优化
- **目标**：提升战斗的视觉和听觉反馈，让玩家清晰感知每一次决策的结果。
- **输入**：现有的 `BattleUIController`、战斗日志系统（`BattleLogger`）。
- **输出**：
  - **伤害数字飘字**：`Unit` 受击时在头顶生成浮动文本（暴击用红色加粗、Miss 用灰色、治疗用绿色）。
  - **战斗日志 UI**：在 Battle UI 中添加滚动日志面板，显示 "Baksa 对 Skeleton 造成了 12 点伤害（暴击！）" 等文本。
  - **镜头反馈**：暴击或击杀时轻微镜头抖动（Camera Shake）。
  - **状态提示**：Buff 施加/消失时在单位头顶显示图标动画。
- **验收标准**：
  - 每次攻击/治疗都有明确的数字飘字和日志记录。
  - 暴击和击杀有更强的视觉反馈（抖动、放大、特殊颜色）。
- **⚠️ 核心代码改动**：无核心逻辑改动，主要在 `BattleUIController` 和表现层代码中新增。

## Risks & Open Questions

1. **核心代码审批清单**：以下改动涉及战斗核心类，需用户/主程确认后方可执行：
   - `CharacterDefinition` 新增字段（Task 1）
   - `Unit` 新增职业资源字段（Task 2）
   - `CombatComponent` 修改伤害计算流程（Task 2、4、6）
   - `Cell`/`ICell` 新增地形字段（Task 6）
   - `RoguelikeBattleReturnHandler` 插入奖励逻辑（Task 3）
   - 若审批不通过，可提供**降级方案**：将装备/职业资源/地形作为纯 Buff 实现，不修改基础类。

2. **数据兼容性**：`PlayerAdventureState` 的 JSON 序列化在新增字段后需要版本迁移（已有 `Version` 字段，可通过升级逻辑处理）。

3. **AI 适配**：新增职业机制、地形效果、范围技能后，AI 行为树需要同步更新（如 AI 会优先站在高地、会躲避火焰地表、会使用 AOE 命中最多敌人的位置）。建议在 Task 2/4/5/6 完成后，追加一个 AI 适配任务。

4. **性能风险**：`AreaEffect` 和 `ChainEffect` 需要扫描范围内单位，在大型战场上（20+ 单位）需确保查询效率。当前 `IUnitManager.GetUnits()` 返回的是内存列表，性能可控。

## 推荐的执行顺序（Phase 1 → Phase 2 → Phase 3）

```
Phase 1（构筑连接，最高优先级）：
  Task 1 → Task 2 → Task 3
  理由：先让"外围选择影响局内"的闭环跑通，这是 Roguelike 的核心价值。

Phase 2（战斗深度，中等优先级）：
  Task 4 → Task 5 → Task 6
  理由：在构筑闭环的基础上，增加局内的策略空间和技能表现力。

Phase 3（体验打磨，可并行）：
  Task 7
  理由：表现层优化可以在任何阶段插入，不影响核心逻辑。
```
