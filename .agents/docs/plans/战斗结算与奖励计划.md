# Task3: 战斗结算与奖励桥接

## 目标

战斗胜利后返回地图时，玩家获得可感知的奖励，强化 Roguelike 循环。

---

## 输入

- `RoguelikeBattleReturnHandler`（当前只更新路径）
- `BattleFlowCoordinator.EndBattleAsync`
- `PlayerAdventureState`

---

## 输出

### 1. BattleRewardSystem（奖励生成系统）

根据战斗难度生成奖励池，难度分级：
- **普通战斗**：基础奖励
- **精英战斗**：中等奖励
- **Boss 战斗**：稀有奖励

### 2. 奖励类型

| 类型 | 说明 | 稀有度影响 |
|------|------|-----------|
| **金币** | 通用货币，用于商店购买 | 数量随难度增加 |
| **装备** | 随机稀有度的装备道具 | Boss 必出稀有装备 |
| **属性提升** | 永久 +1 某项基础属性 | 小概率出现 |
| **技能书** | 学习新技能或替换已有技能 | 中等稀有度 |

### 3. 奖励选择界面

- 战斗胜利后弹出 3 选 1 奖励选择界面
- 玩家选择一项奖励后，其余奖励丢弃
- 选择结果即时生效

### 4. 持久化

- 选择结果写入 `PlayerAdventureState`
- 持久化到 `PlayerPrefs`
- 返回 RoguelikeMap 后，金币和队伍状态同步到地图 HUD

---

## 数据流

```
战斗胜利
  → BattleFlowCoordinator.EndBattleAsync 触发
  → BattleRewardSystem.GenerateRewards(战斗难度)
  → 弹出奖励选择 UI（3 选 1）
  → 玩家选择
  → 奖励应用到 PlayerAdventureState
  → PlayerAdventureStateStore.Save()
  → RoguelikeBattleReturnHandler 更新地图路径
  → 返回 RoguelikeMap，HUD 同步更新
```

---

## 核心代码改动

| 文件 | 改动 |
|------|------|
| `RoguelikeBattleReturnHandler` | 插入奖励结算逻辑，在返回地图前完成奖励选择 |
| `BattleFlowCoordinator` | `EndBattleAsync` 中触发奖励生成流程 |
| `PlayerAdventureState` | 新增金币字段、奖励相关数据结构 |
| `BattleRewardSystem` | 新建：根据难度生成奖励池 |
| `RewardUIController` | 新建：奖励选择界面控制器 |

---

## 验收标准

- 击败 Boss 后必出稀有装备选择；击败普通敌人后获得金币或小属性提升。
- 选择奖励后，下一场战斗中能立即感受到变化（如装备加成生效、新技能可用）。
- 奖励持久化正确，重新进入游戏后奖励不会丢失。

---

## 风险与注意事项

1. **数据兼容性**：`PlayerAdventureState` 新增金币字段需要 JSON 版本迁移
2. **商店系统依赖**：金币奖励的价值依赖于后续商店系统的实现
3. **技能书实现**：需要与现有技能系统对接，确保新技能可以正确添加到角色技能列表
