# 魔剑士恶魔失控形态人工验收 Checklist

本清单对应人工验收账本中的 `MQA-GODOT-DEMONBOUND-POSSESSION`。自动测试已经覆盖确定性规则与状态转换；本次只检查玩家实际能看到、理解和持续游玩的部分。所有测试必须使用 disposable/隔离 Run，不能覆盖正式存档。

## 本轮重点

### 1. `MQA-GODOT-DEMONBOUND-POSSESSION` — 腐化、失控 AI、永久死亡与缺员继续

#### A. 准备三局隔离 Run

- [ ] 只通过 `Tools/godot/Open-GodotDev.ps1` 启动当前 `godot/project.godot`，确认 Editor 标题指向本仓库。
- [ ] 分别建立三局包含魔剑士的 disposable Run：魔剑士 + 法师 + 亚马逊、魔剑士 + 法师 + 死灵法师、魔剑士 + 亚马逊 + 死灵法师。
- [ ] 每局开始时记录 Run seed、队伍、魔剑士初始技能分支；保留进入目标战斗前的 checkpoint/save 副本。

**操作**：正常推进三局 Run，主动使用会增加腐化的技能，记录每次行动前后腐化值，并至少在一局中使用冥想后继续累积到 10。

**预期**：腐化按技能标注成本增长；冥想的减腐与使用限制清晰；腐化到达 10 时仅触发一次附身，之后本场战斗不能再通过冥想退出或重复叠加强化。

**观察**：行动栏成本、左上 BattleUnitPanel 腐化条、`N/10` 数值、冥想按钮禁用原因、战斗事件日志、CheatConsole 与 Godot Output。

**失败保留**：Run seed、队伍、回合、技能、行动前后腐化值、checkpoint/save 副本、截图或短视频，以及第一条异常 Output。

**存档边界**：行动和结算会修改 Run；只使用隔离存档，复现失败前先复制当前 checkpoint，不覆盖原始失败现场。

#### B. 核对附身强化与自动接管

- [ ] 附身瞬间，角色 tint/形态色明显变化，腐化条持续显示并脉冲 `POSSESSED`。
- [ ] 对比附身前后状态卡：六项基础属性均强化，HP/MP 上限及当前值变化可理解，已学非大师技能显示为该分支最高等级；未学技能没有被临时解锁。
- [ ] 玩家输入不再控制附身角色；轮到魔剑士时由 AI 自动完成行动，且阵营标识没有改变。
- [ ] 在同一场战斗布置可攻击的友方、敌方和召唤物，使不同目标分别在距离、击杀价值或技能收益上占优；观察多轮选择。
- [ ] 确认 AI 既可能攻击敌人，也可能攻击友方/友方召唤物；选择随收益变化，不固定优先某一阵营；诱饵不进入附身统一候选池。

**操作**：在至少一场附身战斗中保留敌、友、召唤物混合候选，连续观察附身 AI 行动直至战斗结束。

**预期**：AI 从同一候选池按技能收益、距离与击杀价值选择，合法目标与技能实际可命中目标一致；不会因友伤把魔剑士改成敌方阵营，也不会等待玩家输入或卡住回合。

**观察**：棋盘站位、阵营颜色、目标高亮、技能等级、伤害数字、Turn Order、战斗事件日志、CheatConsole AI 日志与 Godot Output。

**失败保留**：Run seed/RNG state、行动前棋盘截图、所有候选的单位 ID/阵营/格子/HP、AI 选择的技能与目标、完整事件序列和短视频。

**存档边界**：只观察和记录，不用调试操作改写正式存档；若使用测试辅助布置，必须记录具体操作并保持该 Run disposable。

#### C. 核对友方 Down、永久死亡与后续 Run

- [ ] 重放固定布置，直到分别观察到一次普通 Down 和一次永久死亡；永久死亡必须来自附身魔剑士对正式友方造成的致命伤。
- [ ] 永久死亡只结算一次，死者状态明确区别于普通 Down；召唤物、自身或非致命伤不会产生正式队员墓碑。
- [ ] 战斗结束后可以正常结算，不出现 `run.result_invalid_party`，缺员队伍仍能继续 Run。
- [ ] 下一场战斗的 checkpoint、出生单位和 Turn Order 均不再包含永久死亡成员。
- [ ] 永久死亡成员仍保留在最终 Summary 的墓碑/死亡记录中；普通 Down 成员不会被永久移除。
- [ ] 若魔剑士附身后成为己方唯一存活正式队员，消灭全部敌人仍能正常胜利并进入结算。

**操作**：保存致命行动前的 checkpoint，重放直到得到普通 Down 与永久死亡两类结果；分别继续到结算、下一场战斗和最终 Summary。另在可控条件下验证一次“附身魔剑士为唯一幸存者”的胜利路径。

**预期**：友方致命伤有概率成为真正 `Dead`，而不是只有 `Down`；永久死亡成员本 Run 后续不再参战，但历史记录仍存在。所有结果都能继续结算，不软锁、不复活、不重复投骰。

**观察**：战斗事件日志、角色状态、结算页、下一场棋盘与 Turn Order、最终 Summary、CheatConsole 与 Godot Output。

**失败保留**：致命行动前 checkpoint/save、Run seed/RNG state、攻击者/目标/技能/伤害、目标幸运值、事件顺序、结算错误码、下一战阵容、Summary 截图和完整 Output。

**存档边界**：永久死亡会不可逆地改变当前 Run 队伍；必须用 disposable Run。验证完成前保留致命行动前与结算后的两个 save 副本。

## 累计待验收

- 本文只处理 `MQA-GODOT-DEMONBOUND-POSSESSION`。魔剑士动作美术、HUD 通用可读性、Bane 特效、完整 Run 平衡和 Workbench Reload 仍按 [`manual-acceptance.md`](manual-acceptance.md) 中各自的稳定 ID 独立验收，不因本项通过而自动通过。

## 无需重复人工验证

- 不要求人工执行 30-seed 批测；固定种子、确定性重放与统计文件由自动测试覆盖。
- 不要求人工证明精确的幸运概率公式、六维 `+5` 数学值、派生属性公式、技能投影幂等性、目标 tie-break 或 checkpoint 成员集合校验；这些属于 NUnit/GdUnit 自动断言。
- 人工只需确认这些规则在实际 HUD、AI 行动、结算、下一战和 Summary 中表现清楚且不会阻断 Run。

## 环境与收尾

- [ ] 测试期间只保留当前仓库对应的 Godot Editor；不要手动打开第二个 `project.godot`。
- [ ] 每次失败先保留证据和 save，再 Reload 或重试；不要用新运行覆盖失败现场。
- [ ] 三局完成后检查 Godot Output：无与本流程相关的新 error、exception、orphan 或资源加载失败。
- [ ] 关闭或归档 disposable Run，不把测试死亡结果写入正式游戏存档。
- [ ] 将结果按下面格式回复；只有明确回复 `1 OK` 才能把账本状态改为 `passed`。
