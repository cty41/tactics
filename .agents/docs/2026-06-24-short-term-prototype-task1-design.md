## 一句话目标

验证短局 `探索 -> 战斗 -> 结算/掉落 -> 再选择` 是否能形成重复游玩的动力，并确认这种动力首先来自外围闭环，而不只是单场战斗本身。

## 本轮验证立场

本轮同时验证两个问题：

1. 外围 Roguelike 闭环是否能驱动玩家继续推进
2. 单场战斗是否具备基本成立性

但优先级明确如下：

1. 先验证外围闭环是否成立
2. 再验证单场战斗是否足够支撑这个闭环

原因：当前项目已经具备战斗主链和战后结算基础。如果外围闭环本身不驱动继续玩，再继续扩战斗内容会放大错误方向。

## 核心循环定义

本轮原型的最小有效循环定义为：

1. 玩家在 Roguelike 地图上做出路线或节点选择
2. 玩家进入战斗或事件，承担资源损耗、风险和收益波动
3. 结算阶段产生至少一种可带出结果：奖励、损伤、路线变化、撤离压力或配置变化
4. 玩家基于这次结果，决定继续推进、转向、保守运营或撤离

只有当第 4 步确实被第 3 步影响时，这个循环才算有效。

## 单局边界

- 目标单局时长：15-25 分钟
- 目标有效循环次数：至少 3 次
- 单局结束条件：Boss 结算、主动撤离、队伍崩盘
- 本轮允许占位内容和简化数值，但不允许缺失结算反馈

## 必要功能闭环清单

在当前独立开发阶段，`Task 1` 的“闭环证明”不应先用玩家主观感受来判定，而应先回答：系统层面是否已经完成一组足以支撑 `结算 -> 再选择` 的必要功能。

这里的 `再选择` 先收紧为：

- 玩家在固定且已随机生成好的地图节点之间，基于上一轮结算结果，重新决定**先去哪个可达节点**。
- 本轮不要求“队伍状态改变节点可达性”，也不要求“地图层根据队伍状态改写节点类型/内容/拓扑”。
- 节点是否可达，当前只由：
  1. 图连通性
  2. 节点自身状态（如 `visited / reachable / revealed`，若该设计存在）
  决定。

因此，本轮闭环的重点不是“节点是否因状态而被动态改写”，而是：

- **上一轮结算结果是否能稳定写回单局状态，并在下一次节点比较时成为有效上下文。**

本轮最小闭环，至少要先做成以下 6 项：

1. **结算结果必须能写回单局状态**
   - 战斗、补给、商店等节点的结果，必须能稳定写回当前 run state。
   - 至少覆盖：`HP / MP / 死亡状态`、金币、装备/道具变化、成长结果。

2. **地图层必须能读取当前单局状态，并在重新选择节点时保留这些状态上下文**
   - 地图层不要求因队伍状态动态改写节点可达性。
   - 当前阶段更现实的要求是：返回地图后，玩家重新比较可达节点时，系统侧已经持有并可继续消费本轮 run state（例如 `HP / MP / 死亡状态 / Gold / 装备 / 成长结果`）。

3. **补给点 / 战斗点 / 商店点必须共享一套最小结果表达结构**
   - 三类核心节点不要求结果完全一致，但必须能统一表达、统一写回、统一被地图层消费。
   - 推荐最小结构至少覆盖：状态变化、资源变化、成长变化、经济变化。

4. **补给点、战斗点、商店点三类核心节点都必须有最小可用实现**
   - 补给点：能写回 `HP / MP / 死亡后回局口径` 的修复/承接结果。
   - 战斗点：能写回战后成长跃迁或战斗结果。
   - 商店点：能写回金币兑现成现实能力后的结果。
   - 当前最低状态集合先以 `HP / MP / 死亡 / 留尸 / 战后回收装备与消耗品` 为准。

5. **至少存在一条最小地图流程，能把功能链跑通**
   - 必须存在一条在若干步内可跑通的流程：
     `战斗结果 -> 状态写回 -> 后续修复或资源转化 -> 再选择`
   - 这里只要求功能链成立，**不预设**补给点与商店点必须是平行节点，也不预设固定拓扑。
   - 同时不要求地图节点因队伍状态而动态改变类型或内容；只要求玩家在固定可达节点集合中完成一次新的比较。

6. **这条最小地图流程必须能在同一局 run 内连续成立至少 2-3 轮**
   - 不是只做一次性示例。
   - 需要验证：上一轮结算结果被写回之后，下一轮节点评估真的读取并消费了这些状态。

只要上述 6 项还未成立，就不应宣称 `Task 1` 的外围闭环已经被证明成立；此时最多只能说“局部节点功能可运行”或“单轮流程打通”。

## 三条核心假设

### 假设 A：外围选择会改变下一次进入战斗前的决策

玩家在地图上的推进、休整、冒险或保守选择，不应只是换一个节点皮肤，而应真实影响下一次开战前的判断。

### 假设 B：战斗结果会制造继续推进与撤离之间的张力

战斗的价值不只是胜负，而是让玩家在收益、损耗和风险之间做权衡。如果每次战后都只剩“当然继续打”，撤离机制就没有验证价值。

### 假设 C：即使战斗内容量还有限，外围闭环依然能驱动重复开局

本轮原型不要求完整职业池、完整装备池或完整敌人库。只要外围闭环成立，玩家仍应出现“想再开一局试试另一条路线/另一种配置”的动力。

## 成功信号

以下信号至少满足 3 条，且其中前 2 条必须满足，才可判定 Task 1 成功：

1. 玩家愿意连续完成至少 3 次有效循环，而不是打一场就停
2. 每次结算都会产生至少 1 个影响下一次选择的结果
3. 玩家能明确复盘“为什么继续推”“为什么该撤”
4. 即使战斗内容量有限，仍能观察到“再开一局”的动机
5. 地图推进中的节点差异会影响风险偏好，而不只是奖励大小

补充正式判据：

- 一次路线或节点选择，只有在结算后不会将当前小队压缩到仅剩单一、被迫的后续解法，并且能够通过恢复、成长或资源转化扩宽、恢复或强化下一轮的合理解法集合时，才应被视为当前 run 中的合理选择。
- 若一次结算能够稳定改变玩家下一轮的合理解法集合，使玩家既未被压缩为单一路径求生，又因 `HP/MP/死亡状态`、`消耗品变化`、`技能/天赋/属性成长`、`金币/商店机会` 中的一类或多类结果而获得新的推进判断，则可视为 `结算 -> 再选择` 闭环成立。

## 失败信号

以下任一条出现且持续存在，即可判定 Task 1 失败或需要大幅转向：

1. 地图推进、奖励和撤离对下一次选择几乎没有影响
2. 玩家感受到的是重复劳动，而不是持续推进欲
3. 战斗输赢只改变数值，不改变路线、配置或风险判断
4. 单局显著超过 25 分钟，导致外围反馈被战斗时长掩盖
5. 玩家只在意单场战斗胜负，对整个 run 的节奏和抉择没有感知

补充正式判据：

- 若结算结果虽发生变化，但既未改变玩家下一轮的合理解法集合，也未促使玩家在路线、补给、资源分配或风险偏好上产生真实调整，则不应视为 Task 1 的闭环验证成立。
- 若玩家在多次循环后仍然长期沿用同一种路线逻辑，只是机械承受数值变化，而没有因 `HP/MP/死亡状态`、`消耗品变化`、`成长 action` 或 `金币/商店机会` 而重估哪些节点“仍然合理、值得去且能承受”，则说明结算反馈尚未进入决策层。

## 非目标

本轮 Task 1 明确不验证以下内容：

- 完整职业阵容
- 完整装备池和掉落表
- 正式数值平衡
- 完整局外成长系统
- 高完成度美术与叙事包装
- 自动战斗的最终产品定位

这些内容可以服务验证，但不应反客为主，变成 Task 1 的成功条件。

## 对后续任务的约束

Task 2-7 必须服从以下约束：

1. 任何新内容都要回答：它是否增强了 `结算 -> 再选择` 的闭环
2. 任何新系统都要回答：它是否帮助玩家更早形成继续推进或撤离判断
3. 任何新玩法都不能只证明“可实现”，必须证明“会改变下一次选择”

因此后续任务的优先判断逻辑应为：

1. 先补能产生结算反馈和路线张力的内容
2. 再补能提升单场战斗辨识度的内容
3. 最后再考虑减负与自动化是否前置

## 试玩观察口径

后续试玩记录至少要观察以下问题：

1. 这一局中，玩家做了几次真正受上一场结果影响的选择？
2. 玩家是否主动讨论过“继续推还是该撤”？
3. 哪些奖励真的改变了下一场配置，哪些只是数字奖励？
4. 玩家停止游玩的原因，是外围不驱动，还是战斗本身过慢/重复？

补充观察问题：

5. 玩家在每次结算后，下一轮是否仍然保有至少两种他认为“都说得通”的推进方案？如果没有，是因为什么资源或状态把他压缩成了单一路径？
6. 玩家改变路线时，主要是因为哪一类结算结果：`HP/MP/死亡状态`、`消耗品变化`、`技能/天赋/属性成长`，还是 `金币/商店机会`？
7. 玩家选择某条替代路线时，是否能在进入节点前清楚说明：这条路线是在修复当前哪个痛点，或放大当前哪项优势？
8. 玩家是否出现过“虽然地图上还有很多点，但实际上只剩少数几类节点还合理”的感受？如果出现，是由什么结算结果触发的？

如果不能把失败原因拆成“外围问题”与“战斗问题”，就说明本轮原型仍然混淆了验证目标。

## 推荐的后续落地方向

在本基线下，后续最优先推进的不是“更多内容”，而是：

1. 可反复测试的短局战斗切片
2. 能影响下一次选择的最小结算反馈
3. 能制造继续推进/撤离张力的资源损耗与奖励差异

自动战斗、完整 build 深度和大规模敌人库，均应排在上述验证之后。
