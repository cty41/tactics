# ImageGen 单图迭代

## 先查正反案例

生成前先阅读 [`review-casebook.md`](review-casebook.md)，并从 [`../examples/cases.json`](../examples/cases.json) 的 `approved_assets` 选择正式母图。`correct_128.png` 与 `incorrect_128.png` 只用于快速辨认体量、层级和球核错误，不能作为 ImageGen 输入。

`rejected`、`rejected/superseded` 和 `tmp` 中的图片即使某个局部正确，也不得继续编辑。若任务需要的反例尚未留下真实文件，只记录缺口，不得把正确候选误标为反例或人工伪造失败资产。

## 输入图片职责

每次调用前给输入图命名并写清职责：

- **母图**：锁定角色身份、胶囊身体、等距站位和已确认装备；编辑请求必须写出保持不变的区域。
- **犬种/脸部参考**：只迁移耳型、口鼻、眼神和颜色，不迁移参考图比例或完整躯干。
- **武器/姿态参考**：只迁移握点、杆刃结构或骨架；禁止复制写实材质、地图和对方角色。

## 迭代规则

一次只生成一个角色或一个变体。先锁定身体和脚位，再逐步编辑脸部、武器、遮挡层和颜色；在提示中重复标准画布、脚底基线和“胶囊身体不可重绘”。

局部修改要明确屏幕方向与三维层级，例如“枪杆主体在盾牌后，只有枪头在盾牌前”。每个方向都要单独声明近侧手、远侧手、身体和装备的绘制顺序；通用默认只能作为起点，不能覆盖角色已确认的三维关系。如果编辑结果改变了头身比例、脚位或身体宽度，回退到正式资产清单中的正确母图，不继续在错误候选上叠加修改。

## 死亡状态静态图

死亡图必须先区分胶囊地面单位与球形飞行单位，再决定姿态、核心体量、脱手道具和 Tile 锚点。完整规则、当前参考锚点与失败模式见 [`death-state-sprites.md`](death-state-sprites.md)；本文件只负责通用 ImageGen 单图迭代，不重复死亡状态契约。

## 方向变体 / 双原生视图

开始方向变体前先确认母图属于已通过人工审核的胶囊体信徒或胶囊规则怪物。`Tools/artworks/amazon` 的黑白线稿只用于造型设定和风格探索，不得进入正式四方向生产。

当四方向静态图采用“两张原生锚点 + 镜像补齐”时，先锁定已确认的 `down-right` 母图，再单独生成 `up-left` 原生图。`up-left` 必须是新的三分之四背向投影，不能把 `down-right` 水平翻转、旋转或改色后冒充原生背向图。

生成前必须从同角色已确认的 `down-right` 母图制作一张纯核心主体蒙版。胶囊角色的蒙版只保留中央头身胶囊，排除耳朵、口鼻、眼睛、手掌、脚掌和所有装备；飞行角色只保留球核。蒙版只用于记录上下缘、中心、最大宽度和上中下三个截面宽度，并在生成后制作 QA 叠加图；禁止把蒙版粘贴、合成或擦线修补进最终 Sprite。新方向需原生重绘核心轮廓，中段近似平行、下段只能持平或内收。完整 Sprite 包围盒只能检查安全边距和裁切，不能用于缩放或判断主体胖瘦。

母图锁定角色身份、核心主体比例、配色、脚位、装备清单与画布占用；新方向需按目标视角重建头部朝向、脸部可见度、近远耳和肢体、装备前后遮挡与投影。两张原生图必须共用 `256×256 RGBA`、身体中心 `x=128`、脚底基线 `y=236` 和相同安全边距；完整轮廓可以因耳朵、口鼻或装备自然变化。

先按原生解剖学手持关系生成两个锚点图。若后续使用镜像补齐另外两个方向，必须在任务中明确接受武器、盾牌或法术物件的视觉换手。对矛盾、匕首鬼火、法杖等不对称装备，在 `128×128` 预览和 `64×32` Tile 线框中确认手、物件尖端、脸部与脚掌分离。

采用极简无手臂策略时，手掌必须直接嵌入主体边缘：母版至少形成约 `2–4 px`、或手掌宽度约 `20%–30%` 的重叠接触面。不得用细线补画手臂，也不得在删除手臂后保留浮空手掌；托举的法术可以与手掌分离，但手掌本身必须与主体 alpha 连通。

`up-left` 背向三分之四图默认把画面左侧近手绘制在身体前层并完整保留，把画面右侧远手绘制在身体后层并遮住内侧约 `40%–60%`。盾牌、法术和武器仍按各自任务锁定可见范围；不得为了展示装备而交换前后层或让远侧手浮在身体外。

若蒙版叠加暴露双轮廓、后脑鼓包、局部变胖或接缝，必须回到同角色正确 `down-right` 母图重新原生生成。不得继续编辑错误方向候选，也不得通过直接合成核心蒙版来“校准”身体。

每次只生成一个角色的一个方向变体。方向、身体尺寸或脚位错误时，回到最近正确母图重新生成，不在错误候选上重复叠加修改。

## 运行时双原生图接入

当用户明确授权 Godot 运行时美术接入时，导入两张已确认的 `256×256` 原生图，而不是四张预烘焙图片。逻辑方向沿项目等距网格轴解释，运行时映射固定为：East 使用 `up-left + flipX`，West 使用 `down-right + flipX`，North 使用 `up-left`，South 使用 `down-right`。

镜像补齐方向必须在任务中明示接受视觉换手：非对称的矛盾、匕首鬼火、法杖和长柄斧可以左右交换视觉位置，但不能反向修改 `FacingDirection`、移动、攻击目标或 AI 逻辑。新运行时纹理保持 `256×256`、Single Sprite、`128 PPU`、底部 Pivot `(0.5, 0.078125)`；`_128` 预览只留在 `Tools/artworks` 做 QA。

使用 `FourDirectionSpriteVisual` 时只配置根节点的主 `Sprite` Renderer；不要镜像根 Transform，不能翻转 Shadow、Marker、ExplosionAnimation 或其他特效 Renderer。未配置组件的单位必须继续沿用既有 East/West 翻转回退，以保证老资产不回归。

## 外部物件

将武器、耳朵、翅膀和法术当作独立剪影处理：规定长度上限、离地状态、画布安全边距和与身体的前后层级。生成后优先检查 128 预览能否把手、物件尖端、脸和脚分开；不能分开时先调整位置或版本，而不是增加内部排线。
