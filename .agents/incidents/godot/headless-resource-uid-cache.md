# Headless ResourceSaver UID cache boundary

## Observed

The Poison Spear converter saved a new `PoisonBuff.tres` with a `uid://` header and catalog entry. A later normal headless Runtime process rejected that UID as unregistered until the Godot Editor filesystem scan ran.

## Reproduction

1. Run a C# `SceneTree` through `--headless --script`.
2. Create a new Resource path, register an ID, save through `ResourceSaver`, and write the UID into the catalog.
3. Exit that process and immediately run the project in normal headless Runtime mode.
4. A catalog lookup through `ResourceUid.UidToPath` cannot resolve the newly introduced path unless an Editor filesystem scan has updated the project UID cache.

## Cause and resolution

`ResourceUid.AddId` registers an ID in the current process. `ResourceSaver.SetUid` persists the UID into the resource file, but a separate Runtime process does not perform the Editor filesystem scan that discovers newly added project files. The generator now uses `ResourceUid.CreateIdForPath`, `AddId`, and `ResourceSaver.SetUid`, preserves the recorded ledger UID on repeats, and the verification order is:

```text
ResourceSaver generation
→ byte-idempotency repeat
→ headless Editor filesystem scan
→ separate headless Runtime validation
```

The real Poison Spear batch passes this sequence and retains seven identical target hashes and UIDs on a repeated generation.

## Evidence

- `verified_local`: reproduced and fixed on Godot 4.7.1 Mono on 2026-08-09; Runtime validation reports six catalog entries after the Editor scan.
- `official_docs`: https://docs.godotengine.org/en/4.7/classes/class_resourcesaver.html — `set_uid` and `get_resource_id_for_path`; queried 2026-08-09.
- `official_docs`: https://docs.godotengine.org/en/4.7/classes/class_resourceuid.html — `create_id`, `create_id_for_path`, `add_id`, and `set_id`; queried 2026-08-09.
- `verified_local`: local 4.7.1 `GodotSharp.xml` confirms the C# method names used by the converter.

## Scope and invalidation

This applies to newly created resources generated by a standalone headless script and then consumed by another process. Existing imported resources and generation hosted inside a fully initialized Editor may already be registered. Re-evaluate if Godot persists standalone `ResourceUid` cache changes or changes Editor filesystem scanning behavior.
