# Combat Skills Implementation Plan

## Overview

基于设计文档 `.kilo/plans/20260401-new-combat-skills.md`，本计划详细描述 4 个新技能的实现方案，以及对现有系统的修改。

## 现有系统分析

### 架构模式

项目使用 TBSFramework 的 Ability-Command 模式：

```
IAbility (接口)
  ↓
Ability (Unity 基类) → AbilityImpl (纯逻辑实现)
  ↓
具体技能 (HealAbility, AttackAbility, AreaEffectDamageAbility)
  ↓
ICommand (执行命令) → AttackCommand, HealCommand, MultipleTargetAttackCommand
```

### 关键组件

| 文件 | 作用 |
|------|------|
| `IAbility.cs` | 技能接口，定义生命周期方法 |
| `Ability.cs` | Unity MonoBehaviour 基类 |
| `AttackAbilityImpl.cs` | 攻击技能逻辑实现 |
| `AttackCommand.cs` | 攻击命令执行 |
| `ICombatant.cs` | 战斗接口（伤害计算、事件） |
| `CombatComponent.cs` | 战斗组件（暴击、伤害公式） |
| `IUnit.cs` | 单位接口（包含 AbilityUsed 事件） |

### 现有技能示例

**HealAbility** (治疗技能):
- 选择范围内友方单位
- 点击目标执行治疗命令
- 无消耗

**AreaEffectDamageAbility** (范围伤害技能):
- 选择目标格子为中心
- 计算半径内所有单位
- 使用 `MultipleTargetAttackCommand` 对多个目标造成伤害

## 新技能实现方案

### 1. Fireball (火球术)

**设计规格:**
- 效果：范围内造成伤害，并点燃受伤单位
- 范围：4 tiles (施法距离)
- AOE 范围：目标 tile 和相邻的 4 个 tiles (十字形，共 5 格)
- 消耗：3 Mana
- 点燃效果：后续 3 回合每回合造成 1 点伤害

**实现文件:**
```
Assets/Tactics/Scripts/TbsfFork/Scripts/units/abilities/FireballAbility.cs
Assets/Tactics/Scripts/TbsfFork/External/tbsf-common/common/units/abilities/FireballCommand.cs
Assets/Tactics/Scripts/TbsfFork/External/tbsf-common/common/units/buffs/IgniteBuff.cs (新增 Buff 系统)
```

**关键逻辑:**
1. 继承 `ClashOfHeroesAbility` 或 `Ability`
2. 显示阶段：高亮 4 tiles 内的格子作为目标
3. 点击格子后：计算十字形 AOE 范围内的所有单位
4. 执行 `FireballCommand`:
   - 对每个单位造成伤害
   - 施加 `IgniteBuff` (3 回合)
   - 扣除 3 Mana
5. Buff 系统需要在 `IUnit` 上添加 `AddBuff()` 方法和回合开始时的 Buff 触发

**需要新增:**
- Buff 系统基础架构
- `IgniteBuff` 实现
- Mana 消耗逻辑

---

### 2. MeleeHeal (近战治疗) - 替代原有 HealAbility

**设计规格:**
- 消耗：无
- 效果：对相邻友方单位治疗 3 点 HP
- 范围：1 tiles（相邻）

**与原有 HealAbility 的区别:**
| 特性 | 原有 HealAbility | 新 MeleeHeal |
|------|-----------------|-------------|
| 治疗范围 | 可配置 (_healRange) | 固定 1 tile |
| 治疗量 | 可配置 (_healAmount) | 固定 3 HP |
| 视觉效果 | 依赖 IHealHighlighter | 解耦 |
| 网络支持 | 无 | 不需要 |
| Undo 支持 | 无 | 不需要 |

**决策：可以替代原有 HealAbility**

理由：
1. 原有 HealAbility 在 ThirdParty 目录，是示例代码，不是项目核心
2. 原有实现缺少战斗日志集成
3. 原有实现依赖 IHealHighlighter 组件，耦合度高
4. MeleeHeal 固定范围为 1，更符合"近战治疗"的语义
5. 新实现将使用项目的 BattleLogger 集成战斗日志
6. 简化实现（不需要网络和 Undo）

**实现文件:**
```
Assets/Tactics/Scripts/TbsfFork/Scripts/units/abilities/MeleeHealAbility.cs
Assets/Tactics/Scripts/TbsfFork/External/tbsf-common/common/units/abilities/HealCommand.cs
```

**关键逻辑:**
1. 继承 `Ability`
2. 选择阶段：查找相邻 1 tile 内的受伤友方单位
3. 点击目标执行治疗
4. 使用新的 `HealCommand`（简化实现）
5. 集成战斗日志

**HealCommand 实现要点:**
- 简化实现（不需要 Serialize/Deserialize）
- 不需要 Undo 支持
- 移除对 IHealHighlighter 的依赖（视觉效果由其他系统处理）
- 集成战斗日志

### 3. RangedAttack (远程攻击)

**设计规格:**
- 效果：对范围内的单个 unit 造成伤害
- 消耗：无
- 范围：5 tiles
- 限制：攻击者相邻 1 tiles 内不可攻击（防止贴脸）

**实现文件:**
```
Assets/Tactics/Scripts/TbsfFork/Scripts/units/abilities/RangedAttackAbility.cs
Assets/Tactics/Scripts/TbsfFork/External/tbsf-common/common/units/abilities/AttackCommand.cs (复用)
```

**关键逻辑:**
1. 继承 `AttackAbility` 或 `Ability`
2. 选择阶段：查找 5 tiles 内且不在相邻 1 tile 的敌人
3. 使用 `AttackCommand` 执行攻击
4. 需要修改 `IsUnitAttackable` 逻辑或添加额外检查

**修改现有:**
- 可能需要在 `AttackAbilityImpl` 中添加 `MinRange` 参数

### 4. MeleeAttack (近战攻击)

**设计规格:**
- 效果：对范围内的单个 unit 造成伤害
- 消耗：无
- 范围：1 tiles (相邻)

**注意:** 这个技能与现有的 `AttackAbility` 功能重复。现有 `AttackAbility` 使用 `AttackRange` 属性决定范围。

**方案选择:**
1. **方案 A**: 不创建新技能，直接使用现有的 `AttackAbility`，通过配置 `AttackRange = 1`
2. **方案 B**: 创建独立的 `MeleeAttackAbility`，硬编码范围为 1，用于特殊逻辑（如反击、命中判定等）

**推荐方案 A**，除非有特殊机制需要区分。

**接口设计:**
```csharp
public interface IBuff
{
    string BuffName { get; }
    int Duration { get; }
    void OnApplied(IUnit target);
    void OnTurnStart(IUnit target);
    void OnTurnEnd(IUnit target);
    void OnRemoved(IUnit target);
}
```

**IUnit 扩展:**
```csharp
// 在 IUnit.cs 中添加
void AddBuff(IBuff buff);
void RemoveBuff(IBuff buff);
IEnumerable<IBuff> GetBuffs();
```

**Unit 实现:**
```csharp
// 在 TilemapUnit.cs 或 Unit 基类中添加
private readonly List<IBuff> _buffs = new List<IBuff>();

public void AddBuff(IBuff buff)
{
    _buffs.Add(buff);
    buff.OnApplied(this);
}

public void OnTurnStart()
{
    foreach (var buff in _buffs.ToList())
    {
        buff.OnTurnStart(this);
        // 减少持续时间，移除过期的 buff
    }
}
```
